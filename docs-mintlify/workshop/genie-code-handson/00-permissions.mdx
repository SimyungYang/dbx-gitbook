## Part D3: 권한 모델 — RBAC & ABAC

데이터를 만들었으니, 이제 **"누가 어떤 데이터를 볼 수 있는가"**를 정할 차례입니다. 접근 제어를 안 하면 아무나 민감 데이터를 보거나, 반대로 꼭 필요한 사람이 못 보게 됩니다. Unity Catalog는 이를 **두 가지 방식**으로 관리합니다 — 보통 **RBAC로 시작**하고, 민감 데이터가 많아지면 **ABAC로 보완**합니다.

### RBAC — "역할(그룹)에 열쇠를 준다"

- **한 줄로** — 사람마다 일일이 권한을 주지 않고, **역할(그룹)에 권한을 묶어** 부여합니다. 건물에서 사람마다 열쇠를 깎는 대신 "3층 출입 그룹"에 출입증을 주는 것과 같습니다.
- **어떻게** — `GRANT` 명령으로 **securable**(권한을 걸 대상 — 카탈로그 > 스키마 > 테이블/볼륨)에 **privilege**(할 수 있는 일 — `SELECT` 읽기, `MODIFY` 쓰기, `USE SCHEMA` 접근 등)를 줍니다.
- **예** — "분석가 그룹은 `gold` 스키마를 **읽기(SELECT)**만 가능." 분석가가 100명이어도 그룹 하나에 한 번만 부여하면 됩니다.
- 권한은 상위→하위 계층을 탑니다: 테이블을 읽으려면 그 위의 카탈로그·스키마에도 `USE` 권한이 필요합니다.

### ABAC — "라벨(태그)에 규칙을 건다"

- **한 줄로** — 데이터에 **태그(라벨)**를 붙여두고 "이 태그가 붙은 것은 이렇게 다뤄라"는 **정책을 한 번만** 만들면, 태그가 붙은 **모든** 대상에 자동 적용됩니다.
- **어떻게** — 컬럼·테이블에 태그(예: `pii`)를 붙이고 → "`pii` 태그가 붙은 컬럼은 권한 없는 사용자에게 마스킹" 같은 정책을 겁니다.
- **왜 강력한가** — 나중에 새 테이블이 생겨도 **태그만 붙이면** 정책이 자동 적용됩니다. 대상마다 일일이 손대는 RBAC와 달리, ABAC는 "속성이 맞으면 자동"이라 테이블이 수천 개여도 정책 하나로 커버됩니다.

### 언제 무엇을 쓰나

| | **RBAC** | **ABAC** |
|---|---|---|
| 기준 | **누가**(그룹) 접근하나 | 데이터의 **속성(태그)** |
| 부여 | `GRANT`/`REVOKE`로 대상마다 | 태그 + 정책(한 번, 일괄) |
| 대표 예 | 분석가 그룹 → `gold` 스키마 읽기 | `pii` 컬럼 자동 마스킹 |
| 언제 | **기본** — 접근 통제의 출발점 | 민감정보 등 **속성 기반 세밀 통제** 보완 |

> 대부분 **RBAC로 접근을 통제**하고, PII 같은 민감 컬럼이 늘어나면 **ABAC로 정책을 일괄 적용**해 보완합니다. 둘은 배타적이지 않고 함께 씁니다.

> ⚠️ **워크샵 안전 규칙**: 권한 실습은 **본인이 만든 오브젝트(`ccm_factory`)에 대해서만** 합니다. 다른 참가자·공용 오브젝트의 권한은 변경하지 않습니다. 부여 프롬프트는 실제 실행 전 반드시 **계획(Plan)을 읽고** 승인하세요.

### Step 1: 현재 권한 확인

먼저 내 카탈로그에 지금 어떤 GRANT가 걸려 있는지 봅니다.

```
내 카탈로그 ccm_factory의 현재 GRANT를 보여줘. 카탈로그 레벨과 gold 스키마 레벨을 나눠서 표로 정리해줘.
```

### Step 2: 부여 방법 파악 (RBAC)

바로 실행하지 말고, 먼저 방법과 영향 범위를 물어봅니다.

```
특정 그룹에 ccm_factory.gold 스키마의 SELECT 권한을 부여하려고 해.
필요한 GRANT 구문과, 상위 카탈로그/스키마에 USE 권한이 함께 필요한지 알려줘. 아직 실행하지는 마.
```

### Step 3: 태그·정책 개념 확인 (ABAC)

```
ccm_factory에서 PII로 볼 만한 컬럼에 태그를 붙이고, 그 태그 기준으로 마스킹 정책을 거는 ABAC 방식이 어떻게 동작하는지 우리 스키마 예시로 설명해줘.
```

> 💡 RBAC는 "누구에게 무엇을" 직접 주는 방식이라 직관적이고, ABAC는 "속성이 맞으면 자동 적용"이라 오브젝트가 많아질수록 관리가 쉽습니다. 둘은 함께 씁니다.
> 공식 문서: [Unity Catalog 권한](https://docs.databricks.com/en/data-governance/unity-catalog/manage-privileges/index.html) · [ABAC](https://docs.databricks.com/en/data-governance/unity-catalog/abac/index.html)
