Databricks **Genie Code**로 자연어 프롬프트만으로 데이터 파이프라인부터 AI 에이전트까지 End-to-End로 구축하는 1일 핸즈온입니다.

**카메라 모듈(CCM, Compact Camera Module) 스마트팩토리** 데이터를 소재로, 있을 법한 Bronze 원천 데이터를 만들고 → 정제 파이프라인 → 대시보드/Genie → 비정형 처리 → Agent Bricks 에이전트까지 이어집니다.

> 📌 **표기 규칙 — 카탈로그 이름**: 이 가이드는 카탈로그를 편의상 `ccm_factory`로 표기합니다. **공유 워크스페이스**에서는 충돌 방지를 위해 본인 고유 카탈로그 `ccm_factory_<본인ID>`(예: `ccm_factory_hong`)를 만들고, 가이드의 `ccm_factory`를 **본인 카탈로그로 바꿔** 읽으세요. [모듈 0](00-genie-code-intro-setup)에서 이 이름을 Custom Instructions에 등록해 두면, 이후 "내 카탈로그의 …"라고만 해도 Genie Code가 자동으로 본인 카탈로그를 씁니다. (별도 워크스페이스를 배정받았다면 `ccm_factory` 그대로 사용)

## 💡 Genie Code 바이브 코딩 팁 (시작 전 읽기)

**바이브 코딩**이란 코드를 직접 타이핑하지 않고, 원하는 결과를 **자연어로 설명**하면 Genie Code가 코드·쿼리를 대신 작성·실행·검증하는 방식입니다. 아래 요령만 지키면 이 워크샵 전 과정을 매끄럽게 진행할 수 있습니다.

| 팁 | 왜 / 어떻게 |
|------|------------|
| **짧게, 단계별로** | 한 번에 완벽한 대형 프롬프트를 쓰기보다, 작은 단계로 나눠 요청하고 결과를 확인하며 이어갑니다. (되돌리기 어려운 *데이터 생성*만 완결형으로) |
| **테이블은 `@`로 참조** | `@ccm_factory.bronze.aoi_inspection`처럼 @ 멘션하면 Genie Code가 실제 스키마를 읽어 컬럼을 지어내지 않고 정확히 작업합니다 |
| **계획(Plan)을 읽고 승인** | 실행 전 계획을 보여줍니다. 특히 DROP/DELETE/ALTER는 계획을 확인한 뒤 `Allow`를 누르세요 |
| **한 번에 하나씩** | Genie Code가 작업 중(빨간 Stop 버튼)이면 다음 프롬프트를 입력하지 않습니다 — 중복 실행 방지 |
| **에러는 그대로 붙여넣기** | 실패하면 에러 메시지를 그대로 전달하세요. Genie Code가 원인을 읽고 스스로 고칩니다 |
| **출력 형식을 지정** | "표로 요약", "row count만", "상위 10개"처럼 원하는 형태를 명시하면 결과가 깔끔합니다 |
| **비용은 `LIMIT`으로** | 개발·테스트 중에는 `LIMIT 1000`을 습관화해 불필요한 대용량 실행을 줄입니다 |
| **규칙은 Custom Instructions로 한 번만** | 언어·네이밍·안전 규칙을 미리 고정하면 프롬프트마다 반복하지 않아도 됩니다 |
| **막히면 맥락을 보강** | 원하는 결과가 안 나오면 컬럼·조건·예시를 덧붙여 다시 요청하세요 |

> 설정(노력·안전 규칙·Custom Instructions·MCP)은 [모듈 0](00-genie-code-intro-setup)에서 한 번에 끝냅니다.

## 이 워크샵의 목표

- **Genie Code = 만능 빌더**: SQL/Python을 직접 쓰지 않고, 자연어 프롬프트만으로 Databricks의 다양한 기능을 빠르고 안전하게 구축한다
- **안전한 구성 우선**: Genie Code의 "Allow in this thread" 실행 승인, Custom Instructions 안전 규칙, Serverless 제약, MCP 도구 최소권한 프로필을 지킨다
- **제조 도메인 체감**: 수율·불량·OEE·예측정비 같은 실제 스마트팩토리 질문을 데이터로 답하는 경험

## 시나리오 — 왜 카메라 모듈인가

카메라 모듈(CCM) 조립 라인에서 발생하는 제조 실행(MES)·공정(SPC)·검사·설비 텔레메트리 데이터를 소재로 합니다.

- **한 줄 스토리**: "원천 로그가 파편화된 스마트팩토리에서, Genie Code로 신뢰할 수 있는 수율·품질·설비 데이터를 만들고, 누구나 자연어로 물어보고, 에이전트가 대신 분석·안내하게 만든다."
- SMT 실장 → 디스펜싱/본딩 → 리플로우 → Active Alignment(AA) → AOI 검사 → 최종 화질검사로 이어지는 공정 흐름이 명확해 Medallion 아키텍처와 잘 맞습니다.

### 공정 흐름 (데이터가 생성되는 순서)

| 단계 | 공정 | 대표 원천 테이블 |
|------|------|-----------------|
| 1 | 자재 입고 | `material_lot_master` |
| 2 | SMT 실장 | `smt_placement_logs` |
| 3 | 디스펜싱/본딩 | `dispensing_process` |
| 4 | 리플로우 | `reflow_profiles` |
| 5 | Active Alignment (AA) | `active_alignment` |
| 6 | AOI 검사 | `aoi_inspection` |
| 7 | 최종 화질검사 | `final_image_test` |
| — | 전 공정 관통 | `equipment_sensor_logs` / `cleanroom_environment` / `traceability` |

## 안전 구성 원칙 (전 모듈 공통)

Genie Code로 "안전하게" 구성하기 위한 규칙. [모듈 0](00-genie-code-intro-setup)에서 설정하고 끝까지 유지합니다.

| 영역 | 규칙 |
|------|------|
| **실행 승인** | Genie Code에서 **Allow in this thread**를 기본으로 사용. **Always Allow**는 Custom Instructions 안전 규칙(DROP/DELETE 금지 등)으로 보완 후 사용. DROP/DELETE/ALTER는 계획 확인 후 승인 |
| **Custom Instructions** | 기존 테이블 DROP/DELETE 금지, `CREATE OR REPLACE` 사용, 테스트 `LIMIT 1000`, 모든 테이블 COMMENT, Delta·`event_date` 파티션 기본 |
| **Serverless 제약** | R/Scala/RDD/DBFS mount/init script 불가 → Python·SQL·UC Volumes만. `%pip install pyspark` 금지 |
| **MCP 도구** | 워크샵 프로필만 ON. `execute_code`보다 `execute_sql` 우선. "Always allow" 아님 |
| **권한** | 본인 권한 테이블만. Genie Space ≤ 30테이블(GCP 25) |
| **비용** | Genie Code는 소비량 기반 과금 + 실행 컴퓨트 과금. 개발 중 `LIMIT` 습관화 |
