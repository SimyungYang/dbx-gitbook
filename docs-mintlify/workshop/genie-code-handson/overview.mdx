Databricks **Genie Code**로 자연어 프롬프트만으로 데이터 파이프라인부터 AI 에이전트까지 End-to-End로 구축하는 1일 핸즈온입니다.

데이터는 **스마트팩토리**(카메라 모듈 라인) 시나리오를 사용합니다. 있을 법한 Bronze 원천을 만들고 → 정제 파이프라인 → 대시보드/Genie → 비정형 처리 → Agent Bricks 에이전트까지 이어집니다.

> 📌 **표기 규칙 — 카탈로그 이름**
>
> - 이 가이드는 카탈로그를 편의상 `ccm_factory`로 표기합니다.
> - **공유 워크스페이스**에서는 충돌 방지를 위해 본인 고유 카탈로그 `ccm_factory_<본인ID>`(예: `ccm_factory_hong`)를 만들고, 가이드의 `ccm_factory`를 본인 카탈로그로 바꿔 읽으세요.
> - [모듈 0](00-genie-code-intro-setup)에서 이 이름을 Custom Instructions에 등록하면, 이후 "내 카탈로그의 …"만으로도 Genie Code가 자동으로 본인 카탈로그를 씁니다.
> - 별도 워크스페이스를 배정받았다면 `ccm_factory` 그대로 사용.

## 💡 시작 전에 — 바이브 코딩

이 워크샵은 Genie Code로 **바이브 코딩**(자연어로 의도를 설명하면 AI가 코드를 생성·실행·검증)하여 Databricks 기능을 체험하는 과정입니다. 바이브 코딩의 정의·실전 원칙·리스크·체크리스트는 **[바이브 코딩 이해](vibe-coding)** 페이지에 정리했으니 먼저 읽어 보세요.

> 설정(노력·안전 규칙·Custom Instructions)은 [모듈 0](00-genie-code-intro-setup)에서 한 번에 끝냅니다.

## 이 워크샵의 목표

- **Genie Code로 구축**: SQL/Python을 직접 쓰지 않고, 자연어 프롬프트만으로 Databricks의 다양한 기능을 빠르고 안전하게 구축한다
- **안전한 구성 우선**: Genie Code의 "Allow in this thread" 실행 승인, Custom Instructions 안전 규칙, Serverless 제약을 지킨다
- **기능 체감**: 수율·불량·OEE·예측정비 같은 질문을 Genie Code로 데이터에서 답해 보며 Databricks 기능을 몸으로 익힌다 (카메라 모듈은 소재)

| 항목 | 값 |
|------|-----|
| 카탈로그 | `ccm_factory` |

## 안전 구성 원칙 (전 모듈 공통)

Genie Code로 "안전하게" 구성하기 위한 규칙. [모듈 0](00-genie-code-intro-setup)에서 설정하고 끝까지 유지합니다.

| 영역 | 규칙 |
|------|------|
| **실행 승인** | Genie Code에서 **Allow in this thread**를 기본으로 사용. **Always Allow**는 Custom Instructions 안전 규칙(DROP/DELETE 금지 등)으로 보완 후 사용. DROP/DELETE/ALTER는 계획 확인 후 승인 |
| **Custom Instructions** | 기존 테이블 DROP/DELETE 금지, `CREATE OR REPLACE` 사용, 테스트 `LIMIT 1000`, 모든 테이블 COMMENT, Delta·`event_date` 파티션 기본 |
| **Serverless 제약** | R/Scala/RDD/DBFS mount/init script 불가 → Python·SQL·UC Volumes만. `%pip install pyspark` 금지 |
| **권한** | 본인 권한 테이블만. Genie Space ≤ 30테이블(GCP 25) |
| **비용** | Genie Code는 소비량 기반 과금 + 실행 컴퓨트 과금. 개발 중 `LIMIT` 습관화 |
