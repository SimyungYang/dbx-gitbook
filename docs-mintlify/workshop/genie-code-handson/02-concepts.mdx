모듈 2에서 다루는 개념을 초심자 눈높이로 정리합니다. 파이프라인을 짜기 전에 데이터를 먼저 이해하는 이유, 그리고 그때 쓰는 Databricks 도구와 통계 개념을 **무엇 / 왜·언제 / 어떻게**로 설명합니다.

---

### EDA (Exploratory Data Analysis)

- **무엇**: 데이터를 정제·모델링하기 **전에** 그 모습(규모·분포·품질·관계)을 탐색적으로 파악하는 단계.
- **왜·언제**: 원천 로그에는 결측·중복·이상치·규칙 위반이 섞여 있습니다. 이를 모르고 파이프라인을 만들면 잘못된 결과를 자동화하게 됩니다. Silver 정제 규칙은 상상이 아니라 EDA에서 발견한 실제 문제에서 나와야 합니다.
- **어떻게**: 규모·스키마 프로파일링 → 분포 확인 → 품질 진단 → 상관·인사이트 발견 순으로 좁혀 갑니다. EDA는 **읽기 위주** 작업이므로 테이블을 만들거나 바꾸지 않고, 큰 테이블은 `LIMIT`·샘플링으로 비용을 아낍니다.

### DataFrame 프로파일링 (describe / summary)

- **무엇**: DataFrame API의 `describe()`·`summary()`로 수치형 컬럼의 통계(count, mean, stddev, min, 분위수, max)를 한 번에 계산하는 방법.
- **왜·언제**: 컬럼 값이 물리적으로 말이 되는지(예: MTF는 0~100%) 빠르게 점검할 때 씁니다. 값 범위가 규격을 벗어나면 그 자체로 이상치·단위 혼입의 단서가 됩니다.
- **어떻게**: `summary()`는 `describe()`보다 분위수(25/50/75%)까지 포함해 분포의 치우침을 함께 봅니다. 워크샵에서는 MCP 도구 `get_table_stats_and_schema`로 스키마·row count·컬럼 통계를 Genie Code가 바로 조회하게 합니다.

### Data Profile 탭 & 노트북 시각화

- **무엇**: 노트북 셀 결과 위의 **Data Profile** 탭은 컬럼별 분포·결측·최빈값을 자동 요약하고, `display()` 결과에서는 막대·히스토그램·히트맵을 클릭 몇 번으로 만드는 기능.
- **왜·언제**: 코드를 더 짜지 않고도 데이터 첫인상을 잡고 싶을 때. 수율·불량·MTF 현황을 한눈에 보거나, 팀과 화면을 공유하며 논의할 때 유용합니다.
- **어떻게**: 셀 실행 후 결과 상단에서 Table / Visualization / Data Profile을 전환합니다. 차트는 GUI에서 축·집계·그룹을 지정해 생성하며, 이후 대시보드로 옮기기 좋습니다.

### 데이터 품질 차원

- **무엇**: 데이터의 신뢰도를 나누어 보는 관점 — **결측(NULL)·중복·이상치·참조 무결성·비즈니스 규칙 위반·시간 정합성**.
- **왜·언제**: "품질이 나쁘다"를 막연히 말하지 않고 차원별로 쪼개면, 각 문제의 **규모(위반 건수·비율)**를 정량화하고 처리 우선순위를 정할 수 있습니다.
- **어떻게**: 차원별 진단을 하나의 스코어카드(`이슈 유형 | 테이블 | 위반 건수 | 위반 비율 | 영향`)로 모읍니다. 참조 무결성은 마스터에 없는 키를 조인으로 찾고, 중복은 비즈니스 키 기준 그룹핑, 이상치는 물리적 상한/통계 기준으로 판별합니다.

### 상관 vs 인과

- **무엇**: 두 변수가 함께 움직이는 것(상관)과, 하나가 다른 하나의 원인인 것(인과)을 구분하는 사고 원칙.
- **왜·언제**: "특정 공급사 로트의 불량률이 높다" 같은 결과가 나왔을 때. 실제로는 특정 모델·라인에 표본이 몰린 착시(교란 요인)일 수 있습니다.
- **어떻게**: 상관을 발견하면 인과로 단정하지 말고, 모델·라인 같은 변수를 통제해 다시 검증합니다. 세그먼트 차이는 표본 수가 적어 생긴 노이즈일 수 있으니 신뢰구간·최소 표본 기준으로 되물어봅니다. AI가 준 결론에도 같은 방식으로 도전합니다.

### SPC · 공정능력지수 (Cpk)

- **무엇**: SPC(Statistical Process Control, 통계적 공정관리)는 공정 산포를 관리 지표로 다루는 방법이고, Cpk는 공정이 규격(USL/LSL) 안에 얼마나 안정적으로 들어오는지를 나타내는 지수.
- **왜·언제**: 제조 품질의 공용어입니다. 평균이 규격 안이어도 산포가 크면 불량이 생기는데, Cpk는 이 "여유"를 한 숫자로 표현합니다.
- **어떻게**: 파라미터별 평균·표준편차와 규격을 이용해 `Cpk = MIN((USL-mean)/(3σ), (mean-LSL)/(3σ))`로 계산합니다. 통상 **Cpk가 1.33 미만이면 공정 개선 필요** 신호로 봅니다. 규격이 없으면 평균±3σ로 관리한계를 잡습니다.

### 파레토 분석 (80/20)

- **무엇**: 불량을 코드별로 집계해 건수 내림차순으로 세우고 누적 비율선을 함께 그리는 분석. 소수의 항목이 전체 대부분을 차지한다는 80/20 원칙에 기반합니다.
- **왜·언제**: 개선 자원이 한정될 때 "어디부터 손볼지"를 정하는 데 씁니다. 상위 몇 개 불량이 전체의 80%를 차지하는지 보면 우선순위가 분명해집니다.
- **어떻게**: 파레토 차트(막대 = 건수, 선 = 누적 비율)로 시각화한 뒤, 상위 불량을 라인·모델별로 쪼개 어디에 몰리는지 확인합니다.
