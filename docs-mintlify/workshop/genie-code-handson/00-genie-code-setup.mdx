## Part C: 워크샵 사전점검

노트북을 열고 Genie Code에서 아래 프롬프트로 환경을 한 번에 확인합니다.

### Step 1: 노트북 + Serverless 연결

1. 왼쪽 사이드바 **New → Notebook**
2. 이름을 `00_CCM_Workshop_<본인ID>`로 변경 (예: `00_CCM_Workshop_hong`), 언어 **Python**
3. 우측 상단 컴퓨트 → **Serverless** 선택 (초록불 확인)

> ⚠️ **이름 충돌 주의**: 여러 명이 같은 워크스페이스를 공유하면 동일 이름의 **카탈로그·노트북·잡·파이프라인·Genie Space·엔드포인트**가 겹쳐 혼선이 생깁니다(특히 **카탈로그**가 겹치면 서로의 데이터를 덮어씀 — [Part D](#part-d-카탈로그--스키마--볼륨-생성) 참조). **본인 ID(사번·이니셜 등)를 이름에 붙여** 각자 고유하게 만드세요. 이후 단계에서 오브젝트를 만들 때도 같은 원칙을 적용합니다.

### Step 2: Genie Code 패널 열기 & 노력(Effort) 설정

1. 우측 상단 **✨ Genie Code** 아이콘 클릭 (또는 `Cmd+I`) → 사이드 패널
2. 패널 하단 드롭다운에서 노력(Effort)이 **자동**(권장)인지 확인

### Step 3: 사전점검 프롬프트

```
내 Databricks 개발 환경이 준비됐는지 점검해줘:
1. 지금 Serverless 컴퓨트에 연결되어 있는지, Python/SQL 실행이 되는지 간단히 테스트
2. 내가 접근 가능한 카탈로그 목록 (SHOW CATALOGS)
3. %pip install faker 가 되는지 (pyspark 관련 패키지는 테스트하지 마)
4. 현재 워크스페이스 리전과, AI 기능(Genie Code)이 활성 상태인지
결과를 표로 요약해줘.
```

> 계획(Plan)과 "Allow" 승인 버튼이 보이면 Genie Code가 정상 동작하는 것입니다.
