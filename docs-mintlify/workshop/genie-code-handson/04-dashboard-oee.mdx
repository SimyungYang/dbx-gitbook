## Part C: 설비 운영/OEE 대시보드

> 설비별 OEE(가용성×성능×품질)와 예측정비용 건강점수를 보는 설비 운영판.

### Genie Code 프롬프트

> 추이 위젯부터 만들고 KPI·설비 분석·건강 위젯을 한 단계씩 덧붙입니다.

**1단계 —** 대시보드 뼈대 + 추이 2개.

```
gold.oee_by_equipment, gold.equipment_health_score 테이블로 "설비 운영/OEE 대시보드"를 AI/BI 대시보드로 새로 만들어줘. 우선 추이 2개부터: 일별 OEE 추이(최근 30일, 꺾은선, 라인별 색상)와 OEE 3요소(가용성/성능/품질) 추이(Multi-line).
```

**2단계 —** 맨 위에 KPI 카운터 4개 추가.

```
맨 위에 KPI 카운터 4개를 추가해줘: 전체 평균 OEE %(게이지), 평균 가용성(Availability) %, 평균 성능(Performance) %, 평균 품질(Quality) %.
```

**3단계 —** 설비 분석 위젯 3개 추가.

```
설비 분석 위젯 3개를 추가해줘: 설비 유형별 평균 OEE(막대: SMT_MOUNTER/DISPENSER/REFLOW/AA/AOI/FINAL_TESTER), 설비별 OEE 랭킹(가로 막대, 하위 15개 — 개선 대상), 비가동(downtime) 시간 추이(막대: 일별 downtime_min 합계).
```

> ⚠️ `oee_by_equipment`에는 비가동 유형 분해가 없습니다(`downtime_min`·`breakdown_min` 총량만 존재). 사유별(BREAKDOWN/PM/CHANGEOVER/IDLE) 파레토가 필요하면 데이터셋에 `@ccm_factory.silver.downtime_clean`(유형별 레코드 보유)을 추가한 뒤 유형으로 그룹핑하세요.

**4단계 —** 설비 건강 위젯 2개 추가.

```
설비 건강 위젯 2개를 추가해줘: 설비 건강점수 히트맵(X축 날짜, Y축 설비, 색상 health_score — 낮을수록 경고색), 위험 설비 Top 10(health_grade D/F, 주요 위험요인 표시).
```

**5단계 —** 필터 추가.

```
마지막으로 필터를 추가해줘: 날짜 범위, 라인, 설비 유형(equipment_type).
```

### 생성 확인

```
"설비 운영/OEE 대시보드"의 URL과 위젯 목록을 보여줘.
건강점수 히트맵에서 D/F 등급 설비가 경고색으로 구분되는지 확인해줘.
```

## Part D: 위젯 옵션 조정 — 축·집계·그룹

대시보드는 "생성"이 끝이 아닙니다. 만든 위젯의 **축·집계 방식·그룹·필터**를 Genie Code로 바꿔 가며 원하는 뷰로 다듬습니다. 하나씩 조정해 봅니다.

**1단계 —** 먼저 X/Y축을 바꿔본다.

```
생산/수율 운영 대시보드의 일별 수율 추이 차트에서 X축을 일자 대신 라인(line_id)으로, Y축을 평균 수율로 바꿔줘.
```

**2단계 —** 집계(aggregation) 방식 변경.

```
그 차트의 집계를 평균(AVG) 대신 합계(SUM) 생산량과 불량 건수(COUNT)로 바꾸고, 이중 축으로 보여줘.
```

**3단계 —** 그룹/색상 분해(group by).

```
막대를 모델(model_code)별로 그룹핑하고, module_type(AF/OIS/ToF)으로 색상을 나눠줘(stacked).
```

> 💡 `module_type`은 `@ccm_factory.bronze.product_master`의 컬럼입니다. 이 색상 분해를 쓰려면 대상 위젯의 데이터셋을 `product_master`와 `model_code`로 조인하도록 함께 요청하세요.

**4단계 —** 필터·기간·정렬 조정.

```
대시보드에 기간(event_date) 필터와 라인 필터를 추가하고, 라인별 생산 수량 차트는 값 내림차순으로 정렬해줘.
```

**5단계 —** 표시 형식 다듬기.

```
수율은 백분율(소수 1자리), 건수는 천 단위 콤마로 포맷하고, 각 위젯 제목과 축 레이블을 한국어로 정리해줘.
```

> 💡 **왜 이걸 배우나**: 같은 데이터라도 축·집계·그룹을 바꾸면 전혀 다른 인사이트가 나옵니다. Genie Code에게 "무엇을 어떻게 보고 싶은지"만 말하면 위젯 옵션을 대신 조정해 주므로, 대시보드를 빠르게 여러 관점으로 실험할 수 있습니다.

## 차트 유형 가이드 (제조 지표에 맞게)

| 지표 | 권장 차트 | 이유 |
|------|----------|------|
| 수율 / OEE (목표 대비) | 게이지 + 추이 꺾은선 | 목표 달성도와 추세를 동시에 |
| 불량 코드/사유 | 파레토(막대+누적선) | "상위 몇 개가 전체의 80%"를 드러냄 |
| 공정능력 Cpk | 히트맵 / 분포 | 시간·공정별 능력 저하 구간 포착 |
| MTF·틸트 산포 | 박스플롯 / 분포 막대 | 규격 대비 산포·이상 확인 |
| 설비 건강점수 | 히트맵 | 다수 설비×시간을 한 화면에 |
| 구성비(고객/카테고리) | 도넛 / Stacked Bar | 비중 비교 |

> ⚠️ **3D 차트·파이 남발 금지**. 비교가 목적이면 막대, 추세면 꺾은선, 다수×시간이면 히트맵이 정확합니다.

## 보너스: 대시보드를 Databricks App으로 배포

만든 대시보드를 독립 웹 앱으로 배포할 수 있습니다.

```
"설비 운영/OEE 대시보드"를 Databricks Apps로 배포해줘. 완료되면 앱 URL을 알려줘.
```

> 실행 중 Code execution 블록이 나오면 **Run**으로 계속 진행합니다. 화면이 의도대로 표시되지 않으면 증상을 요약해 Genie Code에 디버깅을 요청하세요.

## UI로 직접 만들기 (대안 경로)

Genie Code 프롬프트 대신 UI에서 직접 만들 수도 있습니다:

- 왼쪽 사이드바 → **Dashboards → + Create**
- 데이터셋(SQL)을 추가하고, Genie Code 사이드 패널에 "이 대시보드에 라인별 수율 막대 위젯 추가해줘"처럼 요청하면 위젯 단위로도 도와줍니다.

> 💡 워크샵의 핵심은 **Genie Code로 자연어로 만든다**는 경험입니다. 필요하면 UI + 사이드 패널 조합으로 병행하세요.
