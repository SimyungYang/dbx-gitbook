## Part D: 카탈로그 / 스키마 / 볼륨 생성

데이터를 담기 전에, 담을 **그릇**부터 만듭니다. Unity Catalog는 데이터를 3단계 네임스페이스로 계층화합니다.

- **카탈로그 (catalog)** — 최상위 네임스페이스. 하나의 프로젝트/도메인 경계 (여기서는 `ccm_factory`)
- **스키마 (schema)** — 카탈로그 아래의 "폴더". 테이블·볼륨을 목적별로 묶음 (여기서는 `bronze`/`silver`/`gold`/`quarantine`)
- **테이블 (table)** — 스키마 안의 정형 데이터 (행·열)
- **볼륨 (volume)** — 스키마 안의 비정형 파일 저장소 (PDF·이미지·zip 등)

> 그래서 순서가 **카탈로그 → 스키마 → (테이블/볼륨)** 입니다. 상위 그릇이 있어야 하위를 담을 수 있으므로, 아래에서 카탈로그·스키마·볼륨을 먼저 만든 뒤 [Part D2](#part-d2-시드-데이터-다운로드--적재)에서 테이블을 채웁니다.

```
Unity Catalog에 다음 환경을 설정해줘 (기존 오브젝트가 있으면 DROP하지 말고 스킵):

- 카탈로그: ccm_factory
- 스키마: bronze, silver, gold, quarantine
- 볼륨: bronze 스키마에 raw_files 볼륨 (PDF/이미지 등 비정형 저장용)

각 스키마에 COMMENT:
- bronze: 'Raw 제조/공정/검사/설비 텔레메트리'
- silver: '정제·표준화된 데이터'
- gold: '수율·불량·OEE 등 비즈니스 집계'
- quarantine: '데이터 품질 위반 격리'
```

### 확인

```
ccm_factory 카탈로그의 모든 스키마와 COMMENT를 보여줘.
```

기대 결과:

| 스키마 | 설명 |
|--------|------|
| `bronze` | Raw 제조/공정/검사/설비 텔레메트리 |
| `silver` | 정제·표준화된 데이터 |
| `gold` | 수율·불량·OEE 등 비즈니스 집계 |
| `quarantine` | 데이터 품질 위반 격리 |
