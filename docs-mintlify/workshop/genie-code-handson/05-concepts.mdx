title: "개념: Genie & NL2SQL"

모듈 5는 자연어 질문을 SQL로 바꿔 답하는 Genie를 다룹니다. 대시보드가 "아는 질문"에 답한다면, Genie는 "아직 모르는 즉석 질문"에 답합니다. 이 문서는 Genie의 구성 요소와, 정확도를 끌어올리는 튜닝 요소를 초심자 기준으로 정리합니다.

### Genie & Genie Spaces

- **무엇**: 비개발자가 자연어로 질문하면 AI가 SQL을 생성해 답하는 대화형 분석 기능이 Genie이고, 그 질문·답변이 일어나는 작업 공간이 **Genie Space**입니다.
- **왜·언제**: 대시보드에 없는 즉석 질문("최근 7일 수율이 가장 낮은 라인은?")을 SQL을 모르는 담당자가 스스로 답할 때 씁니다.
- **어떻게(핵심)**: 한 Space에는 관련 테이블 묶음과 그 도메인 지식을 담습니다. 이 워크샵에서는 생산·수율 / 품질·불량 / 설비·OEE 세 Space로 나눕니다. 한 Space는 최대 30테이블(GCP 25)까지 담을 수 있습니다.

### NL2SQL (자연어 → SQL) 원리

- **무엇**: 사람의 자연어 질문을 데이터베이스가 실행할 수 있는 SQL 쿼리로 변환하는 기술입니다.
- **왜·언제**: 데이터 접근의 진입 장벽을 없앱니다. SQL 문법 대신 업무 용어로 물으면 되므로 현장 담당자가 직접 데이터를 탐색합니다.
- **어떻게(핵심)**: Genie는 질문과 함께 테이블 스키마·컬럼 COMMENT·샘플 질문·비즈니스 지침을 컨텍스트로 LLM에 전달해 SQL을 만듭니다. 즉, **모델이 보는 컨텍스트의 품질이 곧 정확도**입니다. 그래서 아래 튜닝 요소가 중요합니다.

### 테이블/컬럼 COMMENT

- **무엇**: 테이블과 각 컬럼에 다는 한국어 설명입니다. 값의 의미, 단위, 범위를 적습니다.
- **왜·언제**: Genie가 컬럼 의미를 이해하는 1차 근거입니다. 정확도 영향이 가장 큰 요소 중 하나입니다. `oee_pct`가 무엇인지 모르면 올바른 쿼리를 못 만듭니다.
- **어떻게(핵심)**: Unity Catalog에 `COMMENT ON COLUMN ...` 형태로 저장하면, Genie가 SQL 생성 시 이 설명을 참고합니다. 예: `oee_pct`에 "종합설비효율(%). 가용성×성능×품질. 85 이상 World Class"처럼 단위·기준을 함께 답니다.

### Curated Questions (샘플 질문)

- **무엇**: 질문과 검증된 정답 SQL을 짝지어 Space에 등록해 두는 예시 질의입니다.
- **왜·언제**: **정확도를 가장 크게 올리는 방법**입니다. 비슷한 질문이 들어오면 Genie가 등록된 SQL 패턴을 참고하므로, 조인·집계 같은 까다로운 부분을 안정적으로 재현합니다.
- **어떻게(핵심)**: Space 설정의 Example queries에 추가하거나 MCP로 일괄 등록합니다. 검증된 SQL이 많을수록 답이 일관됩니다.

### General Instructions

- **무엇**: Space 전체에 적용되는 비즈니스 용어 정의·계산 규칙·출력 형식 지침입니다.
- **왜·언제**: 용어와 규칙을 고정해 답의 일관성을 만들 때 씁니다. "수율은 % 소수점 1자리", "날짜 미지정 시 최근 7일" 같은 규칙을 명시합니다.
- **어떻게(핵심)**: 특히 **임의 정의 방지** 규칙이 중요합니다. "'품질이 나쁘다'의 기준이 불명확하면 임의로 정하지 말고 사용자에게 되물어라"를 넣으면, Genie가 기준을 제멋대로 만들어 잘못 분석하는 일을 막습니다. 지침을 바꾼 뒤에는 New Chat으로 새 대화를 시작해야 반영됩니다.

### Joins & SQL Expressions

- **무엇**: Joins는 테이블 간 올바른 조인 경로(어떤 키로, 어떤 관계로 잇는지) 정의이고, SQL Expressions는 자주 쓰는 Filter·Measure·Dimension 로직을 재사용 가능하게 등록한 것입니다.
- **왜·언제**: "특정 고객 모델의 수율"처럼 여러 테이블을 엮는 질문에서 씁니다. 조인 경로가 없으면 Genie가 조인을 못 하거나 잘못 잇습니다.
- **어떻게(핵심)**: Configure의 Joins 탭에서 `daily_yield_summary ↔ product_master (model_code, Many to One)`처럼 관계를 지정합니다. SQL Expressions로는 "평균 수율=`ROUND(AVG(yield_pct),1)`" 같은 계산을 표준화합니다.

### Genie Agent (데이터 분석 에이전트)

- **무엇**: 여러 Genie Space를 도구로 묶어, 질문 의도에 맞는 Space를 자동으로 골라 답하는 상위 분석 에이전트입니다.
- **왜·언제**: 질문이 어느 영역(수율/품질/설비)에 속하는지 사용자가 매번 고르지 않아도 되게 할 때, 또 여러 영역을 넘나드는 복합 질문에 답할 때 씁니다.
- **어떻게(핵심)**: 3개 Space를 도구로 연결하고 System Prompt에 라우팅 규칙을 줍니다. "불량/MTF/Cpk 질문은 품질·불량 Space" 식입니다. 복합 질문은 여러 Space를 순차 호출한 뒤 결과를 통합합니다.

### Benchmarks

- **무엇**: 질문과 정답 SQL을 등록해 두고, Genie가 생성한 SQL이 정답과 얼마나 일치하는지 자동 평가하는 기능입니다.
- **왜·언제**: 튜닝의 효과를 **정량으로** 확인할 때 씁니다. "정확도 80% → 95%"처럼 개선을 숫자로 추적합니다.
- **어떻게(핵심)**: COMMENT·샘플 질문·Joins를 추가하기 전후로 Benchmark를 돌려 점수 변화를 비교하면, 어떤 튜닝이 효과적이었는지 근거를 갖고 판단할 수 있습니다.

| 개념 | 한 줄 정의 | 이 워크샵에서의 쓰임 |
|------|-----------|--------------------|
| Genie / Genie Spaces | 자연어 질문을 SQL로 답하는 대화형 분석 공간 | 생산·수율 / 품질·불량 / 설비·OEE 3개 Space |
| NL2SQL | 자연어를 SQL로 변환하는 원리 | 컨텍스트 품질이 정확도를 결정 |
| 테이블/컬럼 COMMENT | 값의 의미·단위·범위 설명 | Gold 스키마 전체에 한국어 COMMENT |
| Curated Questions | 검증된 질문+SQL 샘플 등록 | 정확도를 가장 크게 올리는 15개 샘플 |
| General Instructions | 용어·계산·출력 규칙 | 임의 정의 방지 규칙이 핵심 |

| Genie Agent | 여러 Space를 묶은 분석 에이전트 | 3개 Space를 하나의 분석가로 통합 |
| Benchmarks | 생성 SQL vs 정답 SQL 자동 평가 | 튜닝 전후 정확도 정량 추적 |
