모듈 4에서 만드는 운영 대시보드를 이해하려면, 그 밑에 깔린 Databricks 기능과 제조 지표의 의미를 먼저 알아야 합니다. 이 문서는 AI/BI Dashboards가 무엇이고 왜 쓰며 어떻게 동작하는지를 초심자 기준으로 정리합니다.

### AI/BI Dashboards

- **무엇**: SQL 쿼리 결과를 KPI 카운터·차트·필터로 조합해 만드는 Databricks의 대시보드 기능입니다. 별도 BI 도구 없이 Unity Catalog의 테이블을 곧바로 시각화합니다.
- **왜·언제**: 매일 반복해서 보는 "정해진 질문"(오늘 수율은? 라인별 OEE는?)에 답할 때 씁니다. 질문이 고정돼 있으니 화면도 고정해두고 새로고침만 하면 됩니다.
- **어떻게(핵심)**: 대시보드는 데이터를 가져오는 **데이터셋(SQL)**과, 그 결과를 그리는 **위젯**으로 구성됩니다. 조회 시 연결된 SQL Warehouse가 쿼리를 실행하고 최신 데이터를 반영합니다.

### 데이터셋 vs 위젯

- **무엇**: 데이터셋은 대시보드가 참조하는 SQL 쿼리(결과 집합)이고, 위젯은 그 데이터셋을 화면에 표현하는 차트·카운터·표 같은 시각 요소입니다.
- **왜·언제**: 둘을 나눠 이해하면 대시보드 수정이 쉬워집니다. "숫자가 틀렸다"는 데이터셋(쿼리) 문제, "그림이 이상하다"는 위젯(시각화) 문제로 나눠 접근할 수 있습니다.
- **어떻게(핵심)**: 하나의 데이터셋을 여러 위젯이 공유할 수 있습니다. 예를 들어 `daily_yield_summary` 하나로 추이 꺾은선과 라인별 막대를 동시에 그립니다.

### 시각화 유형 (제조 지표에 맞는 차트 선택)

- **무엇**: 막대·꺾은선·게이지·파레토·히트맵·도넛 등 데이터 성격에 맞춰 고르는 차트 종류입니다.
- **왜·언제**: 잘못된 차트는 데이터를 왜곡합니다. 비교는 막대, 추세는 꺾은선, 목표 달성도는 게이지, "상위 몇 개가 전체의 대부분"은 파레토, 다수 항목×시간은 히트맵이 정확합니다.
- **어떻게(핵심)**: 제조 현장에서 자주 쓰는 매핑은 아래와 같습니다.

| 지표 | 권장 차트 | 이유 |
|------|----------|------|
| 수율 / OEE (목표 대비) | 게이지 + 추이 꺾은선 | 달성도와 추세를 동시에 |
| 불량 코드/사유 | 파레토(막대+누적선) | 상위 소수가 전체 대부분임을 드러냄 |
| 공정능력 Cpk | 히트맵 / 분포 | 시간·공정별 능력 저하 구간 포착 |
| 설비 건강점수 | 히트맵 | 다수 설비×시간을 한 화면에 |
| 구성비(고객/카테고리) | 도넛 / Stacked Bar | 비중 비교 |

> 3D 차트나 파이 남발은 피합니다. 비교 목적이면 막대가 눈금 읽기에 정확합니다.

### 필터 & 파라미터

- **무엇**: 대시보드 전체 또는 특정 위젯에 적용해 보는 범위를 좁히는 컨트롤입니다. 날짜 범위, 라인, 모델, 근무조(shift) 등이 대표적입니다.
- **왜·언제**: 같은 화면을 여러 관점으로 재사용할 때 씁니다. 라인 담당자는 자기 라인만, 품질팀은 특정 불량 카테고리만 걸러 봅니다.
- **어떻게(핵심)**: 필터는 연결된 데이터셋의 쿼리 조건(`WHERE`)에 자동 반영됩니다. 기본값(예: 최근 30일)을 지정하면 열자마자 의미 있는 화면이 나옵니다.

### 대시보드를 Databricks App으로 배포

- **무엇**: 완성한 대시보드를 독립된 웹 애플리케이션(Databricks Apps)으로 감싸 배포하는 방법입니다.
- **왜·언제**: 워크스페이스 계정이 없는 현장 담당자에게도 URL 하나로 공유하고 싶을 때 씁니다. 대시보드 화면을 별도 앱처럼 노출합니다.
- **어떻게(핵심)**: 대시보드를 Databricks Apps로 배포하면 앱 URL이 생성됩니다. 서버·인증·호스팅을 플랫폼이 관리하므로 별도 인프라 구성이 필요 없습니다.

### 제조 지표를 대시보드로 보는 의미 (OEE·수율)

- **무엇**: 수율(양품/투입), 직행률(FPY), OEE(가용성×성능×품질), 공정능력(Cpk) 같은 핵심 제조 지표를 한 화면에 모아 보는 것입니다.
- **왜·언제**: 흩어진 raw 데이터로는 "지금 라인이 정상인가"를 판단하기 어렵습니다. 집계된 지표를 시각화하면 이상 징후를 즉시 포착합니다.
- **어떻게(핵심)**: 모듈 3에서 만든 Gold 집계 테이블을 대시보드가 직접 소비합니다. 집계가 미리 돼 있으므로 조회가 빠르고, 지표 정의도 일관됩니다.

## 요약

| 개념 | 한 줄 정의 | 이 워크샵에서의 쓰임 |
|------|-----------|--------------------|
| AI/BI Dashboards | SQL 기반으로 위젯·필터를 조합하는 대시보드 기능 | 수율·품질·OEE 운영 대시보드 3종 제작 |
| 데이터셋 vs 위젯 | 데이터셋=SQL 결과, 위젯=시각 표현 | Gold 테이블을 데이터셋으로, 카운터·차트를 위젯으로 |
| 시각화 유형 | 데이터 성격별 최적 차트 선택 | 수율=게이지, 불량=파레토, 능력=히트맵 |
| 필터 & 파라미터 | 보는 범위를 좁히는 컨트롤 | 날짜·라인·모델·근무조 필터 |
| Databricks Apps 배포 | 대시보드를 독립 웹 앱으로 배포 | OEE 대시보드를 URL로 공유 |
| 제조 지표 | 수율·FPY·OEE·Cpk 등 핵심 KPI | 집계 지표로 라인 상태를 즉시 판단 |
