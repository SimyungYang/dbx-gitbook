## Part B: Genie Agent — 데이터 분석 에이전트

### 개념

Genie Agent는 [05. Genie 에이전트](05-genie-agent)에서 만든 **Genie Space**를 도구로 사용하여, 데이터 질문에 SQL로 답변합니다.

#### Genie Code 프롬프트 (AI Dev Kit MCP)

**1단계 —** 에이전트 뼈대부터.

```
Genie Agent "스마트팩토리 데이터 분석가" 를 만들어줘.
설명: 카메라 모듈 생산 수율, 불량, 설비 OEE, 공정 품질을 분석합니다. LLM 모델은 databricks-claude-sonnet-4.
```

**2단계 —** 모듈5 Genie Space 3개를 도구로 연결.

```
다음 Genie Space 3개를 도구로 연결해줘:
1. "생산/수율 분석" (수율/FPY/택트타임)
2. "품질/불량 분석" (불량 파레토/AA MTF/Cpk/자재 상관)
3. "설비 운영/OEE 분석" (OEE/설비건강/downtime)
```

**3단계 —** System Prompt 설정.

```
System Prompt 를 이렇게 설정해줘:
"당신은 카메라 모듈 스마트팩토리 데이터 분석 전문가입니다.
규칙:
1. 수율/생산 질문 → '생산/수율 분석' Genie Space
2. 불량/품질 질문 → '품질/불량 분석' Genie Space
3. 설비/OEE 질문 → '설비 운영/OEE 분석' Genie Space
4. 숫자 결과는 표로 정리, 추세/비교 시 증감률(%) 포함
5. 한국어로 답변하되 전문 용어는 영문 병기"
```

**4단계 —** 생성 후 테스트.

```
생성 후 테스트:
1. "이번 주 라인2의 수율 추이를 분석해줘"
2. "가장 많이 발생한 불량 코드 Top5는?"
3. "OEE가 가장 낮은 설비 3대를 알려줘"
```

### Genie Agent 생성 확인

```
"스마트팩토리 데이터 분석가" Genie Agent가 정상 생성됐는지,
연결된 Genie Space 3개가 모두 인식되는지 확인해줘.
```

## Part C: Supervisor Agent — 멀티 에이전트 오케스트레이션

### 개념

Supervisor Agent는 사용자 질문의 **의도(intent)**를 파악하여 적절한 하위 에이전트로 라우팅합니다. 복합 질문은 여러 에이전트를 함께 호출합니다.

#### Genie Code 프롬프트 (AI Dev Kit MCP: manage_mas)

**1단계 —** Supervisor 뼈대부터.

```
Supervisor Agent "스마트팩토리 AI 어시스턴트" 를 만들어줘.
설명: 카메라 모듈 제조에 관한 모든 질문에 답하는 통합 AI 어시스턴트. 공정 가이드, 데이터 분석, 불량 대응을 지원합니다. LLM 모델은 databricks-claude-sonnet-4.
```

**2단계 —** 하위 에이전트 2개 연결.

```
하위 에이전트 2개를 연결해줘:
1. "카메라 모듈 제조 가이드" (Knowledge Assistant) — 규격/SOP/트러블슈팅
2. "스마트팩토리 데이터 분석가" (Genie Agent) — 수율/불량/설비 데이터
```

**3단계 —** 라우팅 규칙을 System Prompt 에.

```
System Prompt 의 라우팅 규칙을 설정해줘:
"당신은 카메라 모듈 스마트팩토리 통합 AI 어시스턴트입니다.
## 라우팅 규칙
### Knowledge Assistant로 보낼 질문:
- '~규격은?', '~기준은?', '~하는 방법', '~설정', '~대응'
- 공정 SOP, 품질 기준, 설비 트러블슈팅, 불량 대응
- 예: 'AA 틸트 규격', '리플로우 피크온도 기준', '노즐 픽업불량 대응'
### Genie Agent(데이터 분석)로 보낼 질문:
- '얼마나', '몇 개', '추이', '비교', '분석', '수율', 'OEE'
- 숫자/통계/트렌드가 포함된 질문
- 예: '이번 주 라인2 수율', '불량 Top5', '설비 OEE 순위'
### 두 에이전트 모두 필요한 질문 (원인 분석 + 대응):
- 예: '라인2 MTF 불량이 급증했는데 원인과 대응 방법은?'
  → 먼저 Genie: 라인2 MTF 불량 통계/추세/설비·자재 상관 조회
  → 그 다음 KA: MTF/AA 불량 원인 및 대응 SOP 제공"
```

**4단계 —** 답변 규칙 추가 후 생성.

```
같은 System Prompt 에 답변 규칙도 추가하고 Supervisor Agent 를 생성해줘:
"## 답변 규칙
1. 라우팅 결정을 사용자에게 노출하지 마세요
2. 여러 에이전트 답변은 자연스럽게 하나로 통합
3. 한국어로 답변하되 기술 용어는 영문 병기
4. 답변 끝에 '🔍 관련 질문'으로 후속 질문 2~3개 제안"
```

### Step 2: Supervisor 통합 테스트

> 💡 **테스트 전략**: 5개를 한꺼번에 하지 말고 **단순 → 복잡** 순서로 하나씩. 각 사이에 결과를 확인하고 문제가 있으면 먼저 해결하세요.

| 순서 | 목적 | 프롬프트 | 기대 라우팅 |
|------|------|---------|-----------|
| 1 | KA 라우팅 | "Active Alignment 틸트 허용 규격은?" | → KA |
| 2 | Genie 라우팅 | "이번 주 라인2 수율 추이는?" | → Genie |
| 3 | 하이브리드 | "라인2 MTF 불량 급증, 현황과 대응은?" | → Genie + KA |
| 4 | 의사결정 지원 | "Sup_S7 자재 로트 불량률과 격리 절차는?" | → Genie + KA |
| 5 | 복합 분석 | "리플로우 온도 이상 설비의 불량 영향과 점검 절차" | → Genie + Genie + KA |

**1단계 —** 순수 가이드(→ KA).

```
"스마트팩토리 AI 어시스턴트" 에 물어봐줘: "Active Alignment 공정에서 틸트 허용 규격이 얼마인가요?"
기대: KA가 품질 기준 문서 기반 규격 제공.
```

**2단계 —** 순수 데이터(→ Genie).

```
"이번 주 라인2의 일별 수율 추이를 보여줘"
기대: Genie가 daily_yield_summary 조회.
```

**3단계 —** 하이브리드(→ Genie + KA).

```
"최근 라인2에서 MTF 불량이 많이 늘어난 것 같은데, 현황과 대응 방법을 알려줘"
기대: 1) Genie → aa_quality_trend/defect_pareto 에서 MTF 불량 추세 조회, 2) KA → AA/MTF 불량 원인 및 대응 SOP 제공.
```

**4단계 —** 의사결정 지원(→ Genie + KA).

```
"Sup_S7 공급사 자재 로트의 불량률이 높다는데, 실제 수치와 로트 격리 절차를 알려줘"
기대: 1) Genie → material_defect_correlation 에서 Sup_S7 불량률, 2) KA → 자재 로트 불량 격리/추적 절차.
```

**5단계 —** 복합 분석 + 가이드, 마지막에 종합 표.

```
"리플로우 피크온도가 규격을 벗어난 설비에서 불량이 늘었는지, 원인과 점검 절차는?"
기대: 1) Genie → 해당 설비 불량 통계, 2) Genie → reflow 파라미터 이상 분석, 3) KA → 리플로우 온도 이상 점검 SOP.
그리고 5개 시나리오별로 호출된 에이전트, 응답 시간(초), 답변 품질(1~5점), 라우팅 정확성을 표로 정리해줘.
```
