## Custom Instructions — Genie Code의 "시스템 프롬프트"

Custom Instructions는 Genie Code에게 **항상 이 규칙을 따르라**는 지침을 미리 심어두는 설정입니다. 매 대화에 자동으로 얹히므로, 사실상 이 워크샵의 **시스템 프롬프트** 역할을 합니다. 한 번 설정하면 프롬프트마다 규칙을 반복하지 않아도 됩니다.

적용 레벨은 두 가지입니다.

| 레벨 | 파일 위치 | 적용 범위 | 우선순위 |
|------|----------|----------|:---:|
| **워크스페이스** | `Workspace/.assistant_workspace_instructions.md` | 팀 전체 (조직 표준) | 높음 |
| **개인** | `/Users/{username}/.assistant_instructions.md` | 나만 | 낮음 |

- 워크스페이스 지침이 개인보다 우선 적용됩니다. 최대 약 20,000자.
- Genie Code의 인라인 제안·`/fix`에도 적용됩니다 (Autocomplete 제외).
- 워크샵에서는 아래 내용을 **개인 Custom Instructions**로 설정합니다. Settings(⚙️) → **Custom Instructions**에 붙여넣으세요.
- 붙여넣기 전에 아래 **`ccm_factory_hong` 두 곳을 본인 실제 카탈로그명**(예: 사번·이니셜을 붙인 `ccm_factory_kim`)으로 바꾸세요. 이 한 줄이 **가이드의 모든 `ccm_factory` 프롬프트를 자동으로 내 카탈로그로 연결**하는 핵심입니다.

```markdown
## 기본 규칙
- 한국어로 답변, 기술 용어는 영문 병기
- PySpark 기본 사용 (pandas 대신), SQL은 Databricks SQL 문법
- Serverless 제약 준수: R/Scala/RDD/DBFS mount/init script 금지, %pip install pyspark 금지

## 카탈로그 (중요)
- 내 전용 카탈로그는 `ccm_factory_hong` 이다. (공유 워크스페이스 충돌 방지)
- **가이드/프롬프트에 나오는 `ccm_factory`는 전부 내 카탈로그 `ccm_factory_hong`을 가리킨다.** 모든 SQL·코드에서 `ccm_factory.<schema>.<table>` 는 `ccm_factory_hong.<schema>.<table>` 로 해석·사용하라.

## 네이밍
- 스키마: bronze / silver / gold / quarantine
- 테이블/컬럼: snake_case

## 안전 규칙
- 기존 테이블 DROP/DELETE/UPDATE 금지, CREATE OR REPLACE TABLE 사용
- 개발/테스트 시 LIMIT 1000
- 모든 테이블/컬럼에 COMMENT 추가
- Delta 형식, event_date 파티셔닝 기본

## MCP 도구 활용 (AI Dev Kit)
- Genie Space → manage_genie, 대시보드 → manage_dashboard, Job → manage_jobs
- 파이프라인 → manage_pipeline, KA/Supervisor → manage_ka/manage_mas
- MCP 호출 실패 시 재시도, 노트북 우회를 먼저 제안하지 말 것
```

### 적용 확인

```
Custom Instructions가 잘 적용됐는지 가볍게 확인하고 싶어.
내가 접근 가능한 카탈로그 목록을 조회하는 간단한 코드를 만들어줘.
(카탈로그·데이터는 다음 단계에서 만들 거라, 여기서는 규칙 적용만 볼 거야.)
```

> 답변이 **한국어**인지, **PySpark/Databricks SQL**을 쓰는지, 변수·컬럼이 **snake_case**인지, `LIMIT`·주석 규칙을 지키는지 보세요 — 그러면 정상 적용입니다. (실제 카탈로그 생성은 [카탈로그·스키마·볼륨 생성](00-catalog-setup#카탈로그--스키마--볼륨-생성) 단계에서 합니다.)
