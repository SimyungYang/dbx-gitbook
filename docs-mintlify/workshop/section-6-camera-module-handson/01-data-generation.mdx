## 개요

카메라 모듈(CCM) 조립 라인에서 실제로 발생할 법한 **10개 카테고리, 17개 테이블, 약 250만 건**의 Bronze 데이터를 생성합니다. 공정 흐름을 그대로 반영합니다:

```
자재입고 → SMT실장 → 디스펜싱/본딩 → 리플로우 → Active Alignment(AA) → AOI검사 → 최종화질검사 → 출하
```

데이터는 **실제 있을 법한 분포·상관관계·비정형**을 갖도록 설계했습니다(자재로트↔불량, 설비 노후↔고장 전조, 환경 파티클↔오염불량, 구형 테스터 결측 등). 그래서 이후 NL2SQL·예측 ML·예측정비·RAG·AI 함수 실습이 모두 자연스럽게 이어집니다.

> **Tip**: `Cmd+I` → Agent Mode 전환 후 프롬프트 입력. 코드 생성 시 **Plan 확인 → "Allow in this thread" → Accept all → Run**. "Always Allow"는 누르지 마세요.

## 이 모듈의 두 가지 진행 방식 ★

같은 데이터를 얻는 두 경로가 있습니다. **실제 교육은 (A) 임포트**를 기본으로 하고, (B) 생성은 "Genie Code로 이런 데이터를 만들 수 있다"는 **이해·시연용**으로 함께 다룹니다.

| | (A) 샘플 데이터셋 임포트 — ★ 실제 교육 기본 | (B) Genie Code로 직접 생성 — 시연/이해용 |
|---|---|---|
| **무엇** | 강사가 미리 만든 동일 데이터셋을 빠르게 로드 | 프롬프트로 데이터를 즉석 생성 |
| **왜** | 40명 동시 생성 시 Rate Limit·시간·**참가자별 편차** 회피, 이후 모듈 결과가 모두 재현됨 | Genie Code의 데이터 생성 역량 체감, 원리 이해 |
| **소요** | 수 분 (한 번의 로드) | 테이블당 수십 초~수 분 × 17 |
| **진행** | 아래 **Part A** 프롬프트 1~2개 실행 | 마스터 1~2개만 실제 생성 후, 나머지는 **Part B** 프롬프트를 읽으며 이해 |

> 💡 강사는 사전에 Part B 프롬프트로 데이터셋을 **1회 생성**하고 `parquet`로 공유 볼륨(또는 Delta Sharing/Marketplace)에 올려둡니다. 참가자는 Part A로 임포트만 하면 됩니다.

## Part A: 샘플 데이터셋 임포트 (실제 교육 기본)

> **사전 조건**: 강사가 공유한 시드 데이터 위치를 확인하세요. 아래 예시는 공유 볼륨의 parquet 기준입니다. Delta Sharing/Marketplace를 쓰는 경우 강사 안내를 따르세요.

### 방식 1 — 공유 볼륨의 parquet 로드 (권장)

```
공유 볼륨의 카메라 모듈 공장 시드 데이터를 내 카탈로그로 임포트해줘.

- 소스: /Volumes/main/shared/workshop_seed/ccm_factory/  (하위에 테이블별 parquet 폴더 17개)
- 타겟: ccm_factory.bronze 스키마의 동일 이름 Delta 테이블 17개
- 각 parquet 폴더를 읽어 CREATE OR REPLACE TABLE 로 Delta 저장
- 원본 스키마/컬럼 코멘트를 최대한 보존하고, 없으면 테이블 코멘트를 추가
- 완료 후 17개 테이블의 row count를 표로 보여줘
```

### 방식 2 — Delta Sharing / Marketplace 공유 카탈로그에서 복제

```
Delta Sharing으로 공유된 카탈로그 <shared_catalog>.ccm_seed 의 bronze 테이블 17개를
내 ccm_factory.bronze 로 복제(CTAS)해줘. 완료 후 row count를 확인해줘.
```

### 임포트 검증

```
ccm_factory.bronze 스키마의 테이블 17개가 모두 로드됐는지,
각 테이블 row count와 참조 무결성(serial_id/equipment_id/material_lot_id)이 정상인지 요약해줘.
```

> 임포트가 끝났으면 [데이터 생성 후 종합 검증](#데이터-생성-후-종합-검증)으로 건너뛰거나, 바로 [02. EDA](02-eda)로 진행할 수 있습니다.
> Genie Code의 데이터 생성 능력을 직접 보고 싶으면 아래 **Part B**를 진행하세요.

## Part B: Genie Code로 직접 생성 (시연/이해용)

아래는 강사가 시드 데이터를 만들 때 사용한 실제 프롬프트이자, 참가자가 "Genie Code로 이렇게 만들 수 있다"를 체감하는 자료입니다. **마스터 1~2개(equipment_master 등)만 실제로 실행**해 보고, 나머지는 프롬프트를 읽으며 원리를 이해하는 것을 권장합니다.

각 테이블 프롬프트를 그대로 복사·붙여넣으면 PySpark 기반 생성 코드가 자동으로 만들어집니다.

## 카테고리: Master (가장 먼저 생성) ★

### 테이블 1: equipment_master (설비 마스터)

> 모든 공정 로그의 기준이 되는 설비 마스터. 가장 먼저 생성합니다.

| 컬럼 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `equipment_id` | STRING | 설비 고유 ID | `EQ_L1_AA_01` |
| `equipment_type` | STRING | 설비 유형 | `SMT_MOUNTER`, `DISPENSER`, `REFLOW`, `AA`, `AOI`, `FINAL_TESTER` |
| `line_id` | STRING | 라인 | `LINE_1`~`LINE_6` |
| `station` | STRING | 공정 스테이션 | `SMT`, `DISPENSE`, `REFLOW`, `ALIGN`, `AOI`, `FINAL` |
| `vendor` | STRING | 설비 벤더 | `ASM`, `Fuji`, `Hanwha`, `Nordson`, `Koh_Young`, `TRIOPTICS` |
| `model_no` | STRING | 설비 모델 | `SIPLACE_SX`, `AEROSPRAY_5` |
| `install_date` | DATE | 설치일 | `2022-05-10` |
| `rated_capacity_uph` | INT | 정격 UPH(시간당 생산) | `1200` |
| `status` | STRING | 상태 | `RUNNING`, `IDLE`, `MAINTENANCE`, `DOWN` |

```
카메라 모듈 조립 공장의 설비 마스터 300대를 생성해줘.

조건:
- 테이블: ccm_factory.bronze.equipment_master
- 라인 LINE_1~LINE_6, 각 라인은 공정 스테이션 6종(SMT, DISPENSE, REFLOW, ALIGN, AOI, FINAL)을 보유
- 스테이션별 설비 수를 다르게: SMT_MOUNTER 라인당 3~4대, 나머지는 라인당 1~2대
- equipment_id 형식: "EQ_{line 약자}_{type 약자}_{2자리}" (예: EQ_L1_AA_01)
- vendor는 type에 따라: SMT_MOUNTER→ASM/Fuji/Hanwha, DISPENSER→Nordson, AOI→Koh_Young, FINAL_TESTER/AA→TRIOPTICS
- install_date: 2021-01 ~ 2024-12
- rated_capacity_uph: SMT 1000~1500, 그 외 600~1000
- status 분포: RUNNING(80%), IDLE(10%), MAINTENANCE(7%), DOWN(3%)

Delta 테이블로 저장하고 모든 컬럼에 COMMENT를 달아줘.
```

### 테이블 2: product_master (제품/모델 마스터)

| 컬럼 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `model_code` | STRING | 모델 코드 | `CCM_A_48MP_OIS` |
| `customer` | STRING | 고객 (익명) | `Global_A`, `Global_B`, `Global_C`, `Domestic_D` |
| `module_type` | STRING | 모듈 타입 | `AF`, `OIS`, `ToF` |
| `resolution_mp` | INT | 해상도(MP) | `12`, `48`, `50`, `108` |
| `sensor_type` | STRING | 이미지센서 | `IMX_766`, `S5KGN`, `OV50` |
| `lens_count` | INT | 렌즈 매수 | `5`, `6`, `7` |
| `target_mtf_center` | DOUBLE | MTF 목표(중심) | `85.0` |
| `spec_mtf_min` | DOUBLE | MTF 최소규격 | `70.0` |
| `launch_date` | DATE | 양산 시작 | `2024-03-01` |

```
카메라 모듈 제품(모델) 마스터 60종을 생성해줘.

조건:
- 테이블: ccm_factory.bronze.product_master
- 고객명은 익명으로: Global_A(35%), Global_B(25%), Global_C(20%), Domestic_D(20%)
- module_type 분포: OIS(40%), AF(45%), ToF(15%)
- resolution_mp: 12/48/50/108 중, OIS/ToF는 고화소 비중 높게
- model_code 형식: "CCM_{고객약자}_{화소}MP_{모듈타입}" (예: CCM_A_48MP_OIS)
- target_mtf_center: 80~90, spec_mtf_min: target - 12~18
- lens_count: 5~7 (고화소일수록 많게)
- launch_date: 2023-01 ~ 2025-06

Delta 테이블로 저장하고 COMMENT를 달아줘.
```

### 테이블 3: material_lot_master (자재 로트 마스터)

> 이미지센서·렌즈·VCM 등 입고 자재 로트. 나중에 "특정 자재 로트가 불량과 상관있는지" 분석에 사용합니다.

| 컬럼 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `material_lot_id` | STRING | 자재 로트 ID | `MLOT_SENSOR_20250310_0001` |
| `material_type` | STRING | 자재 유형 | `IMAGE_SENSOR`, `LENS`, `VCM`, `PCB`, `IR_FILTER`, `ADHESIVE` |
| `supplier` | STRING | 공급사 (익명) | `Sup_S1`~`Sup_S8` |
| `incoming_date` | DATE | 입고일 | `2025-03-10` |
| `incoming_qty` | INT | 입고 수량 | `5000` |
| `incoming_inspection_result` | STRING | 수입검사 | `PASS`, `CONDITIONAL_PASS`, `FAIL` |
| `defect_rate_incoming_pct` | DOUBLE | 수입검사 불량률 | `0.8` |
| `spec_grade` | STRING | 등급 | `A`, `B`, `C` |

```
카메라 모듈용 자재 입고 로트 20,000건을 생성해줘.

조건:
- 테이블: ccm_factory.bronze.material_lot_master
- material_type 분포: LENS(25%), IMAGE_SENSOR(20%), VCM(15%), PCB(15%), IR_FILTER(15%), ADHESIVE(10%)
- supplier: Sup_S1~Sup_S8 (일부 공급사는 defect_rate가 의도적으로 높게 — Sup_S7, Sup_S8은 평균의 2~3배)
- material_lot_id 형식: "MLOT_{type약자}_{YYYYMMDD}_{4자리}"
- incoming_date: 2024-06 ~ 2025-12
- incoming_inspection_result: PASS(90%), CONDITIONAL_PASS(8%), FAIL(2%)
- defect_rate_incoming_pct: 대부분 0~2%, 일부 공급사/로트는 3~8%
- spec_grade: A(60%), B(30%), C(10%)

Delta 테이블로 저장하고 COMMENT를 달아줘.
```

Delta로 저장, COMMENT 추가.
```

### 테이블 5: production_events (스테이션 통과 이벤트)

> 시리얼(개별 모듈)이 각 스테이션을 IN/OUT하는 이벤트. 택트타임 산출의 원천.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `event_id` | STRING | 이벤트 ID |
| `serial_id` | STRING | 개별 모듈 시리얼 |
| `wo_id` | STRING | FK → work_orders |
| `station` | STRING | SMT/DISPENSE/REFLOW/ALIGN/AOI/FINAL |
| `equipment_id` | STRING | FK → equipment_master |
| `event_type` | STRING | `IN` / `OUT` |
| `timestamp` | TIMESTAMP | 이벤트 시각 |
| `cycle_time_sec` | INT | 스테이션 체류(초) |
| `operator_id` | STRING | 작업자 |

```
스테이션 통과 이벤트(production_events) 400,000건을 생성해줘.
- 테이블: ccm_factory.bronze.production_events
- serial_id 형식: "SN_{YYYYMMDD}_{7자리}", wo_id는 work_orders에서 샘플링
- 각 시리얼은 공정 순서(SMT→DISPENSE→REFLOW→ALIGN→AOI→FINAL)대로 IN/OUT 쌍이 발생
- equipment_id는 해당 station과 line이 일치하는 설비에서 선택
- cycle_time_sec: SMT 8~15, DISPENSE 10~20, REFLOW 30~60, ALIGN 20~40, AOI 5~12, FINAL 15~30
- [의도적 이슈] 약 1% 레코드는 동일 serial+timestamp 중복(재전송), 약 0.5%는 OUT < IN(시간 역전)
Delta로 저장, COMMENT 추가.
```

### 테이블 6: traceability (제품 이력 계보)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `serial_id` | STRING | 개별 모듈 시리얼 (PK) |
| `wo_id` | STRING | 작업지시 |
| `model_code` | STRING | 모델 |
| `material_lot_ids` | `MAP<STRING,STRING>` | 자재유형→사용 로트ID |
| `station_equipment` | `MAP<STRING,STRING>` | 스테이션→처리 설비ID |
| `operator_ids` | `ARRAY<STRING>` | 관여 작업자 |
| `final_result` | STRING | `PASS`/`FAIL`/`REWORK` |

```
