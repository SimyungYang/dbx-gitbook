## 개요

지금까지(모듈 2~5)는 **정형 데이터**(수율·불량·OEE 수치)를 다뤘습니다. 하지만 현장 지식의 상당 부분은 **비정형**입니다 — 필드 리턴 리포트의 증상 서술, 8D 품질 리포트 PDF, 설비/공정 SOP 문서, AOI 불량 이미지.

이 모듈에서는 SQL **AI 함수**로 비정형을 정형화·분류·추출하여, 대시보드·Genie·RAG가 소비할 수 있는 **AI Ready Data**로 만듭니다.

| 다룰 비정형 | 소스 | AI 함수 |
|-----------|------|---------|
| 필드 리턴 증상/분석 (자연어) | `bronze.field_returns` | `ai_classify`, `ai_extract`, `ai_summarize` |
| 8D 품질 리포트 (PDF) | `bronze.raw_files` 볼륨 | `ai_parse_document` → `ai_extract` |
| AOI 불량 이미지 | `bronze.raw_files` 볼륨 | `ai_query` (Vision LLM) |

> 이 모듈의 산출물(정형화된 인사이트, 파싱된 문서)은 **[모듈 7 Agent Bricks](07-agent-bricks)** 의 Knowledge Assistant 지식 소스가 됩니다.

> **Tip**: AI 함수는 서빙 엔드포인트를 호출하므로 과금됩니다. **항상 `LIMIT`으로 소량 테스트 후** 전체에 적용하세요.

## Part A: 텍스트 AI 함수 — 필드 리턴 분석

`field_returns.failure_symptom`(자연어 증상)과 `analysis_result`(자연어 분석)를 AI로 분류·추출합니다.

### A-1. 데이터 훑어보기

```
ccm_factory.bronze.field_returns에서 failure_symptom, analysis_result, root_cause_code를
10건만 보여줘. 어떤 자연어 텍스트가 들어있는지 확인하고 싶어.
```

### A-2. `ai_classify` — 증상을 근본원인 카테고리로 분류

Genie Code에 아래를 요청하면 SQL AI 함수를 생성·실행합니다:

```
ccm_factory.bronze.field_returns의 failure_symptom(한국어 증상 텍스트)을
ai_classify로 다음 5개 근본원인 카테고리 중 하나로 분류해줘:
ALIGNMENT, ACTUATOR, BONDING, CONTAMINATION, SENSOR

- 먼저 LIMIT 20으로 테스트
- 결과 컬럼: rma_id, failure_symptom, 기존 root_cause_code, ai_predicted_cause
- 실제 사용할 SQL도 보여줘
```

생성될 SQL 형태(참고):

```sql
SELECT
  rma_id,
  failure_symptom,
  root_cause_code,
  ai_classify(failure_symptom,
    ARRAY('ALIGNMENT','ACTUATOR','BONDING','CONTAMINATION','SENSOR')
  ) AS ai_predicted_cause
FROM ccm_factory.bronze.field_returns
LIMIT 20
```

### A-3. `ai_extract` — 구조화 추출

```
field_returns.failure_symptom + analysis_result를 결합한 텍스트에서
ai_extract로 다음 3개 항목을 구조화 추출해줘 (LIMIT 20):
- symptom(증상), defect_location(불량 부위), suspected_cause(의심 원인)
결과를 표로 보여주고 SQL도 알려줘.
```

참고 SQL:

```sql
SELECT
  rma_id,
  ai_extract(
    CONCAT(failure_symptom, ' / ', analysis_result),
    ARRAY('symptom', 'defect_location', 'suspected_cause')
  ) AS extracted
FROM ccm_factory.bronze.field_returns
LIMIT 20
```

### A-4. `ai_summarize` — 모델별 리턴 요약

```
모델(model_code)별로 최근 필드 리턴 증상들을 ai_summarize로 3문장 요약해줘.
model_code, return_count, summary 컬럼으로. Global_A 고객 모델 위주로 LIMIT 10.
```

### A-5. 검증 — AI 분류 vs 기존 root_cause_code 일치율

```
방금 ai_classify로 예측한 ai_predicted_cause와 기존 root_cause_code의 일치율을 계산해줘.
- 전체 일치율(%)
- 카테고리별 혼동행렬(confusion matrix)
- 가장 자주 틀리는 카테고리 쌍
불일치가 많으면 원인(레이블 정의 모호 등)도 추정해줘.
```

> 💡 **AI 결과에 도전하기**: 일치율이 낮은 카테고리는 레이블 설명을 프롬프트에 추가(`ai_classify`에 few-shot 힌트)하면 개선됩니다. "ACTUATOR = VCM/OIS 액추에이터 응답·구동 불량" 같은 정의를 붙여 재실행해 보세요.
