## 개요

EDA(Exploratory Data Analysis, 탐색적 데이터 분석)는 데이터를 정제·모델링하기 **전에** 그 모습을 파악하는 단계입니다. 카메라 모듈 공장 Bronze 데이터에는 현실 세계처럼 **결측·중복·이상치·규칙 위반·참조 무결성 문제**가 섞여 있습니다. 이 모듈에서는 Genie Code로:

1. **규모와 구조**를 프로파일링하고
2. **분포**(수율·불량·MTF)를 살펴보고
3. **품질 이슈**를 정량적으로 진단하고
4. **상관·인사이트**(자재↔불량, 설비↔고장, 환경↔오염)를 발견한 뒤
5. 그 발견을 **Silver 변환 규칙**으로 정리해 다음 모듈([03. 파이프라인](03-transformation-pipeline))로 넘깁니다.

> **안전 규칙**: EDA는 **읽기 위주**입니다. 테이블을 만들거나 바꾸지 않습니다. 큰 테이블은 습관적으로 `LIMIT`/샘플링을 붙여 컴퓨트 비용을 아끼세요. Genie Code가 DROP/DELETE를 제안하면 승인하지 마세요.

## Part A: 스키마 & 규모 프로파일링

먼저 전체 지형을 파악합니다.

### 전체 테이블 개요

```
ccm_factory.bronze 스키마의 모든 테이블에 대해 다음을 표로 보여줘:
1. 테이블명, row count, 컬럼 수
2. 각 테이블의 대략적 용도 (COMMENT 기반)
3. 시간 컬럼이 있으면 min/max 타임스탬프 범위
읽기 전용으로만 조회하고, 큰 테이블은 근사치(예: 샘플 또는 메타데이터)를 활용해도 좋아.
```

### 핵심 테이블 컬럼 통계

```
다음 3개 핵심 테이블의 수치형 컬럼 통계(count, mean, stddev, min, 25%, 50%, 75%, max)를 보여줘:
- ccm_factory.bronze.active_alignment (mtf_center_pct, mtf_corner_pct, tilt_x_arcmin, tilt_y_arcmin, focus_z_um)
- ccm_factory.bronze.final_image_test (mtf_sfr_center, dead_pixel_count, particle_count, snr_db, distortion_pct)
- ccm_factory.bronze.equipment_sensor_logs (temperature_c, vibration_mm_s, vacuum_kpa, motor_current_a)
각 컬럼의 값 범위가 물리적으로 말이 되는지(예: MTF는 0~100%) 코멘트도 붙여줘.
```

### NULL 비율 상위 컬럼

```
ccm_factory.bronze의 주요 테이블(final_image_test, dispensing_process, active_alignment, aoi_inspection)에 대해
컬럼별 NULL 비율을 계산하고, NULL 비율이 높은 상위 5개 컬럼을 테이블별로 보여줘.
```

> ✅ `final_image_test.snr_db`가 약 4% NULL, `dispensing_process.uv_dose_mj`가 SENSOR_BOND에서 NULL(정상)이면서 LENS_BOND 일부에서도 NULL(약 3%, 잠재 이슈)로 나오면 데이터가 의도대로 준비된 것입니다.

## Part B: 분포 탐색

숫자만 보지 말고 **분포의 모양**을 봅니다.

### 수율 / 판정 분포

```
카메라 모듈 최종 판정 현황을 분석해줘:
1. final_image_test.test_result (PASS/FAIL) 비율
2. active_alignment.aa_result (PASS/FAIL/RETRY) 비율
3. traceability.final_result (PASS/FAIL/REWORK) 비율
4. 라인(line_id)별, 모델(model_code)별 FAIL 비율 상위 10개
결과를 막대 차트로 시각화해줘.
```

### MTF(해상력) 분포 — 카메라 모듈의 핵심 품질지표

```
active_alignment의 mtf_center_pct 와 final_image_test의 mtf_sfr_center 분포를 히스토그램으로 보여줘.
- product_master의 spec_mtf_min 규격선을 기준으로, 규격 미달 비율도 계산
- module_type(AF/OIS/ToF)별로 MTF 분포가 어떻게 다른지 비교
- 규격을 넘는 이상치(mtf > 100 등)가 보이면 표시
```

> 💡 MTF(Modulation Transfer Function)는 렌즈-센서 정렬 품질을 나타내는 해상력 지표입니다. 중심(center)보다 코너(corner)가 낮은 것이 정상이며, 코너 MTF가 급락하면 틸트(tilt) 불량을 의심합니다.

### 설비/라인/모델 차원 분포

```
생산·불량을 여러 차원으로 쪼개서 보여줘:
1. 라인(line_id)별 생산량(traceability 기준)과 불량률
2. 설비 유형(equipment_type)별 처리 건수 (production_events 조인)
3. 모델(model_code)별·고객(customer)별 생산 비중 (도넛 차트)
4. 근무조(shift)별 불량률 비교 (DAY/SWING/NIGHT)
시각화도 함께 만들어줘.
```

## Part C: 데이터 품질 진단 ★

Bronze에는 현실 세계처럼 품질 문제가 섞여 있습니다. 이를 **정량적으로** 찾아냅니다.

### 품질 스코어카드

```
ccm_factory.bronze 전체에 대해 데이터 품질 리포트를 만들어줘:

1. 참조 무결성:
   - production_events / active_alignment / aoi_inspection / final_image_test 의 equipment_id 가 equipment_master 에 없는 건수
   - traceability / production_events 의 serial 관련 참조가 어긋나는 건수
   - defect_events 등의 material 참조가 material_lot_master 에 없는 건수
2. 중복: production_events 에서 동일 (serial_id, timestamp) 중복 건수
3. 이상치:
   - active_alignment.mtf_center_pct > 100 건수
   - equipment_sensor_logs.temperature_c > 200 건수
   - smt_placement_logs.placement_offset_x_um 이 비정상적으로 큰 값(예: 절대값 500 초과 — mm 단위 혼입 의심) 건수
4. 결측: final_image_test.snr_db NULL 비율, dispensing_process 에서 LENS_BOND 인데 uv_dose_mj NULL 인 비율
5. 시간 역전: production_events 에서 같은 serial+station 의 OUT timestamp < IN timestamp 건수
6. 비즈니스 규칙 위반: aoi_inspection 에서 defect_flag=false 인데 defect_type 이 채워진 건수

결과를 "이슈 유형 | 테이블 | 위반 건수 | 위반 비율 | 영향" 스코어카드 표로 정리해줘.
```

### 진단 결과 해석 & 우선순위

```
위 품질 리포트 결과를 보고, Silver 변환에서 먼저 처리해야 할 이슈를 우선순위로 정리해줘.
각 이슈에 대해: (1) 왜 문제인지 (2) 어떤 분석/집계를 왜곡시키는지 (3) 권장 처리 방법(제거/보정/플래그/격리)을 알려줘.
```

## Part D: 상관 & 인사이트 탐색

단일 테이블을 넘어 **관계**를 봅니다. 여기서 나온 가설이 이후 Genie·ML의 소재가 됩니다.

### 자재 로트 ↔ 불량 상관

```
특정 자재 공급사/로트가 불량과 상관있는지 분석해줘:
- traceability 로 시리얼별 사용 자재 로트(material_lot_ids)를 펼치고, defect_events / final_image_test 의 불량과 조인
- 공급사(supplier)별 불량률을 계산하고, 평균 대비 유의하게 높은 공급사를 찾아줘
- material_lot_master.defect_rate_incoming(수입검사 불량률)과 실제 생산 불량률의 상관도 봐줘
결과를 공급사별 불량률 막대 차트로 보여줘.
```

> ✅ `Sup_S7`, `Sup_S8`의 불량률이 평균의 2~3배로 나오면 데이터의 의도된 상관이 잘 살아있는 것입니다.

### 설비 상태 ↔ 고장(비가동) 상관

```
설비 노후/이상 신호가 고장으로 이어지는지 분석해줘:
- equipment_sensor_logs 에서 설비별 temperature_c, vibration_mm_s 의 일별 추세를 계산
- equipment_downtime 에서 downtime_type='BREAKDOWN' 발생 설비/시점과 비교
- BREAKDOWN 직전 구간에서 온도/진동이 상승 추세였는지 확인
온도·진동 추세와 고장 시점을 같이 볼 수 있는 시각화를 만들어줘.
```

### 클린룸 환경 ↔ 오염 불량 시간 상관

```
클린룸 파티클 급증이 오염 불량과 시간적으로 연관되는지 분석해줘:
- cleanroom_environment 의 particle_0_3um 이 급증한 라인×시간대를 찾고
- 같은 라인×시간대의 defect_events 중 defect_category='CONTAMINATION' 건수와 비교
- 파티클 스파이크 이후 일정 시간 내 오염 불량이 증가하는 패턴이 있는지 확인해줘
```

### AA 공정 ↔ 최종 화질 결과 연계

```
Active Alignment 품질이 최종 화질 판정으로 이어지는지 검증해줘:
- active_alignment.mtf_center_pct, tilt_x/y_arcmin 과 final_image_test.test_result 를 serial 기준 조인
- AA 단계 MTF가 낮거나 tilt가 큰 시리얼이 최종에서 FAIL 되는 비율이 높은지 확인
- tilt 절대값 구간별 최종 FAIL률을 표로 보여줘
```

> 💡 **AI 결과에 도전하기**: 상관을 봤다면 인과를 단정하지 말고 되물어보세요 —
> ```
> 방금 나온 "Sup_S8 로트의 불량률이 높다"는 결과가, 특정 모델이나 특정 라인에 몰려서 생긴 착시는 아닌지
> 모델·라인을 통제해서 다시 검증해줘. 교란 요인이 있으면 알려줘.
> ```

> 💡 **또 하나의 도전**: 데이터셋 전체에서 흥미로운 인사이트 3가지를 스스로 뽑게 해보세요 —
> ```
> ccm_factory.bronze 전체를 살펴보고, 품질/수율 개선에 도움될 흥미로운 인사이트 3가지를 근거 쿼리와 함께 제시해줘.
> ```

## Part E: EDA → Silver 변환 규칙 도출

EDA에서 찾은 문제를 다음 모듈의 **정제 규칙**으로 정리합니다. 이 표가 [03. 파이프라인](03-transformation-pipeline)의 입력이 됩니다.

```
지금까지의 EDA 결과를 종합해서, Bronze → Silver 변환 규칙을 표로 정리해줘.
컬럼: 대상 테이블 | 발견한 이슈 | 처리 방법(제거/보정/플래그/격리) | 근거
```

### 예상 정리 결과 (참고)

| 대상 테이블 | 발견한 이슈 | 처리 방법 | 근거 |
|------------|-----------|----------|------|
| production_events | (serial, timestamp) 중복 | 최신 1건만 유지(DEDUP) | 택트타임·처리량 과집계 방지 |
| production_events | OUT < IN 시간 역전 | 해당 쌍 제거 | 음수 체류시간 방지 |
| active_alignment | mtf_center_pct > 100 | 클리핑 또는 NULL 처리 | 물리적으로 불가능한 값 |
| equipment_sensor_logs | temperature_c > 200 | 이상치 NULL/필터 | 센서 스파이크 |
| smt_placement_logs | offset 단위 혼입(mm/um) | 단위 표준화(µm) | 부호/스케일 왜곡 |
| final_image_test | snr_db NULL(구형 테스터) | 결측 플래그 + 분석 시 제외 | 평균 왜곡 방지 |
| dispensing_process | LENS_BOND인데 uv_dose_mj NULL | 잠재 불량 플래그로 격리 | 경화 부족 추적 |
| aoi_inspection | defect_flag=false인데 defect_type 존재 | 규칙 위반 격리(quarantine) | 불량 통계 왜곡 |
| 전 테이블 | 마스터에 없는 equipment_id/material_lot_id | quarantine 스키마로 분리 | 조인 손실·집계 오류 방지 |
