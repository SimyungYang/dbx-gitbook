## 개요

Gold 테이블을 기반으로:
1. **Genie Space 3개**: 생산·수율 / 품질·불량 / 설비·OEE 분석 공간
2. **정확도 고도화** ⭐: 컬럼 COMMENT, 샘플 질문, General Instructions, Joins로 SQL 생성 정확도를 끌어올린다
3. **Genie Agent**: 3개 Space를 하나의 분석 에이전트로 통합

> ⚠️ Genie Space는 **최대 30테이블**(GCP 25). 스페이스별로 관련 Gold + 필요한 마스터만 담습니다.

## Part A: Genie Space 3개 생성

> 💡 `manage_genie` MCP 도구가 필요합니다. 실패하면 사이드바 **Genie → + New**로 UI에서 만들 수 있습니다.

### Genie Space 1: 생산·수율 분석

```
다음 설정으로 Genie Space를 만들어줘.

이름: 생산·수율 분석
설명: 카메라 모듈 라인의 생산 실적, 수율, 직행률(FPY), 택트타임을 자연어로 분석합니다.

포함 테이블:
- ccm_factory.gold.daily_yield_summary
- ccm_factory.gold.first_pass_yield
- ccm_factory.gold.station_cycle_time
- ccm_factory.bronze.product_master
- ccm_factory.bronze.equipment_master

General Instructions:
- 수율(yield)은 % 단위, 소수점 1자리로 표시
- 날짜 필터가 없으면 최근 7일 기준
- 라인은 LINE_1~LINE_6, 모델은 model_code로 식별
- 결과가 10행 이상이면 Top 10으로 제한하고 "전체 N건 중 Top 10" 표시
- 고객명은 익명(Global_A/B/C, Domestic_D)이므로 그대로 사용
```

### Genie Space 2: 품질·불량 분석

```
다음 설정으로 Genie Space를 만들어줘.

이름: 품질·불량 분석
설명: 불량 파레토, 자재 로트별 불량 상관, AA(Active Alignment) MTF 품질, 공정능력(Cpk)을 분석합니다.

포함 테이블:
- ccm_factory.gold.defect_pareto
- ccm_factory.gold.material_defect_correlation
- ccm_factory.gold.aa_quality_trend
- ccm_factory.gold.spc_process_capability
- ccm_factory.silver.final_test_clean
- ccm_factory.bronze.material_lot_master

General Instructions:
- 불량률은 % 단위, MTF는 pct 단위(0~100)
- "규격 미달"은 mtf_center < 모델의 spec_mtf_min 기준
- Cpk는 소수점 2자리, "공정능력 부족"은 Cpk < 1.33
- 자재 공급사는 Sup_S1~S8로 식별
- 날짜 미지정 시 최근 7일
```

### Genie Space 3: 설비·OEE 분석

```
다음 설정으로 Genie Space를 만들어줘.

이름: 설비·OEE 분석
설명: 설비별 OEE(종합설비효율), 설비 건강 점수, 비가동(downtime)을 분석합니다.

포함 테이블:
- ccm_factory.gold.oee_by_equipment
- ccm_factory.gold.equipment_health_score
- ccm_factory.bronze.equipment_downtime
- ccm_factory.bronze.equipment_master

General Instructions:
- OEE = 가용성 × 성능 × 품질, % 단위 소수점 1자리
- "문제 설비"는 OEE < 75% 또는 health_score < 60
- downtime은 분(min) 단위, 유형은 BREAKDOWN/PM/CHANGEOVER/IDLE
- 설비는 equipment_id로 식별, 라인/유형 질문 시 equipment_master 조인
```

## Part B: Genie 정확도 고도화 ⭐ (가장 중요)

> Genie Space를 만드는 건 쉽지만, **정확한 답**을 내게 만드는 건 튜닝이 필요합니다. 아래 5요소가 정확도를 결정합니다.

| # | 요소 | 영향도 | 설명 |
|---|------|-------|------|
| 1 | **테이블/컬럼 COMMENT** | ★★★★★ | Genie가 컬럼 의미를 이해하는 핵심 |
| 2 | **샘플 질문 (Curated Q&A)** | ★★★★★ | 검증된 SQL 패턴을 학습시킴 |
| 3 | **General Instructions** | ★★★★☆ | 비즈니스 용어·계산 규칙·출력 형식 |
| 4 | **테이블 간 Joins** | ★★★★☆ | 올바른 조인 경로 안내 |
| 5 | **Trusted Assets(인증 쿼리)** | ★★★☆☆ | 자주 쓰는 복잡 쿼리 재사용 |

### Step 1: 테이블/컬럼 COMMENT 일괄 추가

```
ccm_factory.gold 스키마의 모든 테이블과 컬럼에 한국어 COMMENT를 추가해줘.

규칙:
- 테이블 COMMENT: 비즈니스 담당자가 이해할 수 있는 설명 (50자 이내)
- 컬럼 COMMENT: 값의 의미, 단위, 범위 포함

예시:
COMMENT ON COLUMN ccm_factory.gold.daily_yield_summary.yield_pct IS
  '일 수율(%). (양품 수 / 투입 수) × 100. 범위 0~100';
COMMENT ON COLUMN ccm_factory.gold.oee_by_equipment.oee_pct IS
  '종합설비효율(%). 가용성×성능×품질. 85 이상이 World Class';
COMMENT ON COLUMN ccm_factory.gold.spc_process_capability.cpk IS
  '공정능력지수. 1.33 이상이 관리 기준, 1.0 미만은 개선 필요';

모든 Gold 테이블의 모든 컬럼에 COMMENT를 달아줘.
```

### Step 2: 샘플 질문 (Curated Questions) 등록 ⭐⭐⭐

> **정확도를 가장 크게 올리는 방법**입니다. 검증된 SQL을 샘플로 등록하면, 비슷한 질문에 그 패턴을 참고합니다.
>
> **등록 방법**: (1) `manage_genie` MCP로 일괄 등록, 또는 (2) Genie Space 화면 → ⚙️ Settings → "Example queries" → "+ Add".

MCP 일괄 등록 프롬프트:
```
"생산·수율 분석"과 "품질·불량 분석" Genie Space에 아래 샘플 질문과 검증된 SQL을 등록해줘.
```

#### 생산·수율 Space — 샘플 질문

**질문 1**: 최근 7일간 라인별 수율 Top/Bottom
```sql
SELECT
  line_id,
  ROUND(AVG(yield_pct), 1) AS avg_yield_pct,
  SUM(input_qty) AS total_input,
  SUM(good_qty) AS total_good
FROM ccm_factory.gold.daily_yield_summary
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY line_id
ORDER BY avg_yield_pct ASC
```

**질문 2**: 모델별 평균 수율과 목표 대비 갭
```sql
SELECT
  y.model_code,
  p.customer,
  p.module_type,
  ROUND(AVG(y.yield_pct), 1) AS avg_yield_pct,
  COUNT(DISTINCT y.event_date) AS days
FROM ccm_factory.gold.daily_yield_summary y
JOIN ccm_factory.bronze.product_master p ON y.model_code = p.model_code
WHERE y.event_date >= CURRENT_DATE - INTERVAL 30 DAYS
GROUP BY y.model_code, p.customer, p.module_type
ORDER BY avg_yield_pct ASC
LIMIT 10
```

**질문 3**: 스테이션별 직행률(FPY)이 가장 낮은 공정은?
```sql
SELECT
  station,
  ROUND(AVG(fpy_pct), 1) AS avg_fpy_pct,
  SUM(pass_qty) AS pass_qty,
  SUM(input_qty) AS input_qty
FROM ccm_factory.gold.first_pass_yield
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY station
ORDER BY avg_fpy_pct ASC
```

**질문 4**: 최근 한 달 수율이 증가 추세인지 감소 추세인지?
```sql
WITH weekly AS (
  SELECT
    DATE_TRUNC('week', event_date) AS week_start,
    ROUND(AVG(yield_pct), 1) AS avg_yield
  FROM ccm_factory.gold.daily_yield_summary
  WHERE event_date >= CURRENT_DATE - INTERVAL 30 DAYS
  GROUP BY DATE_TRUNC('week', event_date)
)
SELECT
  week_start,
  avg_yield,
  ROUND(avg_yield - LAG(avg_yield) OVER (ORDER BY week_start), 1) AS wow_change
FROM weekly
ORDER BY week_start
```

**질문 5**: 병목 스테이션은? (택트타임이 가장 긴 공정)
```sql
SELECT
  station,
  ROUND(AVG(avg_cycle_time_sec), 1) AS avg_cycle_sec,
  ROUND(PERCENTILE(avg_cycle_time_sec, 0.95), 1) AS p95_cycle_sec
FROM ccm_factory.gold.station_cycle_time
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY station
ORDER BY avg_cycle_sec DESC
```

#### 품질·불량 Space — 샘플 질문

**질문 6**: 이번 주 불량 파레토 Top 10 (불량 코드별)
```sql
SELECT
  defect_code,
  defect_category,
  SUM(defect_count) AS total_defects,
  ROUND(SUM(defect_count) * 100.0 / SUM(SUM(defect_count)) OVER (), 1) AS pct_of_total
FROM ccm_factory.gold.defect_pareto
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY defect_code, defect_category
ORDER BY total_defects DESC
LIMIT 10
```

**질문 7**: Sup_S7 자재 로트의 불량률이 평균보다 높은가?
```sql
SELECT
  supplier,
  ROUND(AVG(defect_rate_pct), 2) AS avg_defect_rate,
  SUM(defect_qty) AS total_defects,
  SUM(used_qty) AS total_used
FROM ccm_factory.gold.material_defect_correlation
WHERE event_date >= CURRENT_DATE - INTERVAL 30 DAYS
GROUP BY supplier
ORDER BY avg_defect_rate DESC
```

**질문 8**: MTF 규격 미달 비율이 높은 모델은?
```sql
SELECT
  model_code,
  ROUND(AVG(mtf_center_avg), 1) AS avg_mtf_center,
  ROUND(AVG(below_spec_pct), 1) AS avg_below_spec_pct
FROM ccm_factory.gold.aa_quality_trend
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY model_code
ORDER BY avg_below_spec_pct DESC
LIMIT 10
```

**질문 9**: 공정능력(Cpk)이 관리 기준(1.33) 미만인 공정 파라미터는?
```sql
SELECT
  process_name,
  parameter_name,
  ROUND(AVG(cpk), 2) AS avg_cpk,
  ROUND(AVG(mean_value), 2) AS mean_value
FROM ccm_factory.gold.spc_process_capability
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY process_name, parameter_name
HAVING AVG(cpk) < 1.33
ORDER BY avg_cpk ASC
```

**질문 10**: 불량 카테고리별 폐기(SCRAP) vs 재작업(REWORK) 비중
```sql
SELECT
  defect_category,
  SUM(CASE WHEN disposition = 'SCRAP' THEN defect_count ELSE 0 END) AS scrap_qty,
  SUM(CASE WHEN disposition = 'REWORK' THEN defect_count ELSE 0 END) AS rework_qty,
  ROUND(SUM(CASE WHEN disposition = 'SCRAP' THEN defect_count ELSE 0 END) * 100.0
    / NULLIF(SUM(defect_count), 0), 1) AS scrap_pct
FROM ccm_factory.gold.defect_pareto
WHERE event_date >= CURRENT_DATE - INTERVAL 30 DAYS
GROUP BY defect_category
ORDER BY scrap_qty DESC
```

#### 설비·OEE Space — 샘플 질문

**질문 11**: OEE가 가장 낮은 설비 Bottom 5
```sql
SELECT
  o.equipment_id,
  e.equipment_type,
  e.line_id,
  ROUND(AVG(o.oee_pct), 1) AS avg_oee,
  ROUND(AVG(o.availability_pct), 1) AS availability,
  ROUND(AVG(o.performance_pct), 1) AS performance,
  ROUND(AVG(o.quality_pct), 1) AS quality
FROM ccm_factory.gold.oee_by_equipment o
JOIN ccm_factory.bronze.equipment_master e ON o.equipment_id = e.equipment_id
WHERE o.event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY o.equipment_id, e.equipment_type, e.line_id
ORDER BY avg_oee ASC
LIMIT 5
```

**질문 12**: 건강 점수가 낮아 정비가 필요한 설비는?
```sql
SELECT
  h.equipment_id,
  e.equipment_type,
  ROUND(AVG(h.health_score), 1) AS avg_health,
  ANY_VALUE(h.risk_factors) AS risk_factors
FROM ccm_factory.gold.equipment_health_score h
JOIN ccm_factory.bronze.equipment_master e ON h.equipment_id = e.equipment_id
WHERE h.event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY h.equipment_id, e.equipment_type
HAVING AVG(h.health_score) < 60
ORDER BY avg_health ASC
```

**질문 13**: 비가동 사유(reason_code)별 손실 시간 Top 10
```sql
SELECT
  downtime_type,
  reason_code,
  COUNT(*) AS occurrences,
  ROUND(SUM(duration_min), 0) AS total_downtime_min
FROM ccm_factory.bronze.equipment_downtime
WHERE start_time >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY downtime_type, reason_code
ORDER BY total_downtime_min DESC
LIMIT 10
```

**질문 14**: 라인별 평균 OEE 비교
```sql
SELECT
  e.line_id,
  ROUND(AVG(o.oee_pct), 1) AS avg_oee,
  COUNT(DISTINCT o.equipment_id) AS equipment_count
FROM ccm_factory.gold.oee_by_equipment o
JOIN ccm_factory.bronze.equipment_master e ON o.equipment_id = e.equipment_id
WHERE o.event_date >= CURRENT_DATE - INTERVAL 7 DAYS
GROUP BY e.line_id
ORDER BY avg_oee DESC
```

**질문 15**: BREAKDOWN이 가장 잦은 설비 유형은?
```sql
SELECT
  e.equipment_type,
  COUNT(*) AS breakdown_count,
  ROUND(AVG(d.duration_min), 0) AS avg_repair_min
FROM ccm_factory.bronze.equipment_downtime d
JOIN ccm_factory.bronze.equipment_master e ON d.equipment_id = e.equipment_id
WHERE d.downtime_type = 'BREAKDOWN'
  AND d.start_time >= CURRENT_DATE - INTERVAL 30 DAYS
GROUP BY e.equipment_type
ORDER BY breakdown_count DESC
```

### Step 3: General Instructions 상세 설정

> ⚠️ Instructions 변경 후에는 반드시 **New Chat**을 눌러 새 대화를 시작하세요. 기존 대화에는 이전 지침 컨텍스트가 남습니다.

품질·불량 Space의 General Instructions 예시:

```
## 비즈니스 용어 정의
- "수율(Yield)": (양품 수 / 투입 수) × 100
- "직행률(FPY, First Pass Yield)": 재작업 없이 한 번에 통과한 비율
- "OEE": 가용성 × 성능 × 품질 (종합설비효율)
- "Cpk": 공정능력지수. 1.33 이상 관리기준, 1.0 미만 개선 필요
- "규격 미달": mtf_center가 해당 모델 spec_mtf_min 미만
- "문제 설비": OEE < 75% 또는 health_score < 60
- "프라임 시프트": DAY 근무조(주간)

## 계산 규칙
- 비율 계산 시 분모가 0이면 NULLIF 사용
- 날짜 필터 미지정 시 최근 7일
- 수율/OEE/불량률은 % 소수점 1자리, Cpk는 소수점 2자리
- 공급사는 Sup_S1~S8, 라인은 LINE_1~6로 식별

## 분석 규칙 (임의 정의 방지) ★
- 기준이 명확하지 않으면 임의로 정의해서 분석하지 말 것
- 더 정확한 정보가 필요하면 사용자에게 반드시 질문할 것
  (예: "'품질이 나쁘다'의 기준을 수율/불량률/MTF 중 무엇으로 볼까요?")
```

> 💡 **임의 정의 방지**가 핵심입니다. 이 규칙이 없으면 Genie가 "품질 나쁜 라인"의 기준을 제멋대로 정해 분석합니다.

### Step 4: Joins 설정

Genie Space Configure → **Joins** 탭에서 조인 경로를 정의합니다:

| Left Table | Right Table | Join Key | 관계 |
|-----------|------------|----------|------|
| daily_yield_summary | product_master | model_code | Many to One |
| oee_by_equipment | equipment_master | equipment_id | Many to One |
| material_defect_correlation | material_lot_master | supplier | Many to One |
| aa_quality_trend | product_master | model_code | Many to One |

> Joins를 설정하지 않으면 "특정 고객 모델의 수율" 같은 질문에서 Genie가 조인을 못 하거나 잘못합니다.

### Step 5: SQL Expressions (재사용 로직)

| 유형 | 이름 | SQL | 설명 |
|------|------|-----|------|
| **Filter** | 관리기준 미달 공정 | `cpk < 1.33` | Cpk 부족 필터 |
| **Measure** | 평균 수율 | `ROUND(AVG(yield_pct), 1)` | 소수점 1자리 |
| **Dimension** | 근무조 구분 | `CASE WHEN shift='DAY' THEN '주간' WHEN shift='SWING' THEN '오후' ELSE '야간' END` | 근무조 한글화 |

| 탭 | 용도 |
|---|------|
| **About** | 이름·설명·SQL Warehouse 연결 |
| **Data** | 테이블 추가/제거, 테이블 설명, 동의어 |
| **Instructions** | 위 General Instructions |
| **Joins** | 위 조인 설정 |
| **SQL Expressions** | Filter/Measure/Dimension |
| **SQL Queries** | Example query(샘플 질문) 등록 |

> **Benchmarks**: 질문 + 정답 SQL을 등록하면 Genie 생성 SQL이 정답과 얼마나 일치하는지 자동 평가합니다. "정확도 80% → 95%"를 정량 추적할 수 있어, 튜닝 전후 비교에 유용합니다.

## Part C: Genie Agent — 데이터 분석 에이전트

3개 Genie Space를 도구로 묶어, 질문 의도에 맞는 Space를 자동 선택하는 분석 에이전트를 만듭니다.

```
다음 Genie Space들을 도구로 사용하는 Genie Agent를 만들어줘.

이름: 스마트팩토리 데이터 분석가
설명: 카메라 모듈 공장의 생산·수율, 품질·불량, 설비·OEE를 분석합니다.
연결할 Genie Space:
  1. "생산·수율 분석" (수율/FPY/택트타임)
  2. "품질·불량 분석" (불량/자재상관/MTF/Cpk)
  3. "설비·OEE 분석" (OEE/설비건강/downtime)
LLM 모델: databricks-claude-sonnet-4

System Prompt:
"당신은 카메라 모듈 스마트팩토리 데이터 분석 전문가입니다.
규칙:
1. 수율/생산/택트 질문 → '생산·수율 분석' Space
2. 불량/품질/MTF/Cpk/자재 질문 → '품질·불량 분석' Space
3. 설비/OEE/정비/downtime 질문 → '설비·OEE 분석' Space
4. 복합 질문은 여러 Space를 순차 호출 후 통합
5. 숫자는 표로 정리, 추세/비교 시 증감률(%) 포함
6. 한국어로 답변하되 전문 용어는 영문 병기"

생성 후 테스트:
1. "이번 주 수율이 가장 낮은 라인과, 그 라인의 주요 불량 코드는?"
2. "OEE가 낮은 설비 3개와 각 설비의 비가동 사유는?"
3. "Sup_S7 자재를 쓴 모델의 불량률이 다른 자재보다 높은가?"
```

### 생성 확인

```
"스마트팩토리 데이터 분석가" Genie Agent가 정상 생성됐고, 연결된 Genie Space 3개를 모두 인식하는지 확인해줘.
```

## Part D: Genie Space Agent 모드 — 인사이트 도출 체인

Genie Space에서 Chat 대신 **Agent 모드**를 쓰면 단일 질의를 넘어 다단계 분석이 가능합니다.

**1단계 — 탐색**:
```
전체 데이터에서 지난 30일 수율/품질/설비 관점의 흥미로운 인사이트를 3가지 뽑아줘.
```

**2단계 — 전략**:
```
방금 도출한 인사이트를 바탕으로 수율 향상 우선순위 3가지를 제안해줘.
```

**3단계 — 검증**:
```
그 중 데이터로 검증 가능한 것을 골라, 검증에 필요한 추가 분석 쿼리를 만들고 실행해줘.
```

> 💡 **Chat vs Agent**: Chat은 단일 SQL 질의, Agent는 여러 쿼리를 조합한 복합 분석·리서치에 적합합니다.

## 핵심 포인트 정리

| 배운 것 | 왜 중요한가 |
|---------|-----------|
| Genie Space 생성 | 비개발자가 SQL 없이 수율·불량·설비를 탐색 |
| 컬럼 COMMENT | Genie가 제조 지표의 의미를 "이해"하는 핵심 |
| 샘플 질문 등록 | **정확도를 가장 크게 올리는 방법** — 검증된 SQL 학습 |
| General Instructions | 수율/OEE/Cpk 용어와 임의정의 방지 규칙 |
| Joins·Benchmarks | 올바른 조인 + 정확도 정량 추적 |
| Genie Agent | 3개 Space를 하나의 분석가로 통합 |
