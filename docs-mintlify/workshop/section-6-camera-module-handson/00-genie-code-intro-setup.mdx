## Part A: Genie Code란?

일반 코딩 AI(ChatGPT/Copilot)와의 결정적 차이는 **Databricks 환경을 직접 안다**는 점입니다.

| | ChatGPT / Copilot | **Genie Code** |
|---|---|---|
| 테이블 스키마 | 사용자가 알려줘야 | **Unity Catalog에서 자동 읽음** |
| 코드 실행 | 생성만 | **직접 실행 + 결과 확인 + 에러 자동 수정** |
| 데이터 탐색 | 불가 | **테이블 검색·샘플 조회·프로파일링** |
| 작업 범위 | 코드 조각 | **계획→실행→검증→수정 자동 반복** |
| 환각 | 컬럼명 지어냄 | **실제 메타데이터 기반, 환각 최소화** |

### 어디서 쓰나 — 6개 제품 영역

노트북 · SQL Editor · AI/BI 대시보드 · Lakeflow Pipeline Editor · MLflow · Jobs. 각 화면 우측 상단 **✨ 아이콘** 또는 `Cmd+I`로 사이드 패널을 엽니다.

### Chat Mode vs Agent Mode

| | Chat Mode | **Agent Mode (이 워크샵)** |
|---|---|---|
| 동작 | 인라인 코드 제안 | 자율 계획→코드→실행→검증→수정 |
| 실행 | 사용자가 직접 | **코드 실행 전 승인(Allow) 요청** |
| 적합 | 빠른 완성/설명 | 복잡한 EDA·파이프라인·에이전트 |

> 이 핸즈온은 전 과정 **Agent Mode**로 진행합니다.

### 비용 구조 (한 줄 요약)

- **Genie Code 사용은 과금됩니다** — 소비량 기반(consumption). 정확한 요율은 공식 가격 정책을 확인하세요.
- **두 축의 비용**: ① Genie Code 사용(프롬프트 → 계획·코드/쿼리 생성) + ② 생성된 코드/쿼리를 돌리는 **컴퓨트** 비용
- **절감 팁**: 개발·테스트 중 `LIMIT 1000` 습관화, 불필요한 대용량·반복 실행 지양
- 데이터 보호는 유지 — 사용자 데이터로 모델을 학습하지 않음(Zero Data Retention). *과금 여부와는 별개.*

## Part B: 안전하게 쓰는 법 ★ (이 워크샵의 원칙)

> 자연어로 뭐든 시킬 수 있다는 건, 실수로 뭐든 지울 수도 있다는 뜻입니다. 아래 규칙으로 **안전하게** 씁니다.

### B-1. 실행 승인은 사람이 쥔다

| 규칙 | 이유 |
|------|------|
| **"Allow in this thread"만 클릭** | 이번 대화에서만 해당 작업 허용 |
| **"Always Allow" 절대 금지** ❌ | 이후 모든 파괴적 작업이 자동 승인됨 |
| DROP/DELETE/ALTER는 **계획(Plan)을 읽고** 승인 | 의도치 않은 삭제 방지 |
| Genie Code가 작업 중이면(빨간 Stop 버튼) 다음 프롬프트 입력 금지 | 중복 실행 방지 |

### B-2. Serverless 제약 (가장 흔한 차단 원인)

Genie Code는 Serverless 위에서 돕니다. 아래는 **안 됩니다** → Python·SQL·UC Volumes로 대체:

| 안 되는 것 | 대안 |
|-----------|------|
| R / Scala / Spark RDD | Python / SQL / DataFrame API |
| `dbutils.fs.mount` (DBFS 마운트) | Unity Catalog Volumes |
| Init Script, JAR/Maven | `%pip install` (단, `pyspark`는 금지 — 세션 중단) |
| `os.environ` 환경변수 | Databricks Widgets |
| UDF 내부 인터넷 접근 | 노트북 코드에서 직접 호출 |

### B-3. 권한·제한

- 본인 UC 권한이 있는 테이블만 읽기/쓰기 가능 (다른 사용자 데이터·Genie 대화 접근 불가)
- Genie Space는 **최대 30테이블** (GCP 25) → 초과 시 뷰로 사전 결합
- MCP 도구는 **최대 20개** 활성화

### B-4. ⚠️ 서울리전 사전 확인

서울리전(`ap-northeast-2`)에서 Genie Code가 안 되면, 관리자가 워크스페이스 설정에서
**"Enforce data processing within workspace Geography for AI features"**를 확인/조정해야 합니다 (Cross-Geo).

## Part C: 워크샵 사전점검

노트북을 열고 Genie Code Agent Mode에서 아래 프롬프트로 환경을 한 번에 확인합니다.

### Step 1: 노트북 + Serverless 연결

1. 왼쪽 사이드바 **New → Notebook**
2. 이름을 `00_CCM_Workshop`으로 변경, 언어 **Python**
3. 우측 상단 컴퓨트 → **Serverless** 선택 (초록불 확인)

### Step 2: Genie Code Agent Mode 켜기

1. 우측 상단 **✨ Genie Code** 아이콘 클릭 → 사이드 패널
2. 하단 드롭다운에서 **Agent** 선택

### Step 3: 사전점검 프롬프트

```
워크샵 사전 확인을 해줘:
1. 지금 Serverless 컴퓨트에 연결되어 있는지, Python/SQL 실행이 되는지 간단히 테스트
2. 내가 접근 가능한 카탈로그 목록 (SHOW CATALOGS)
3. %pip install faker 가 되는지 (pyspark 관련 패키지는 테스트하지 마)
4. 현재 워크스페이스 리전과, AI 기능(Genie Code)이 활성 상태인지
결과를 표로 요약해줘.
```

> Plan이 뜨고 "Allow" 버튼이 보이면 Agent Mode 정상입니다.

## Part E: Custom Instructions — 안전 규칙 고정

Genie Code Settings(⚙️) → **Custom Instructions**에 아래를 붙여넣습니다. 한 번 설정하면 매 프롬프트마다 반복하지 않아도 됩니다.

```markdown
## 기본 규칙
- 한국어로 답변, 기술 용어는 영문 병기
- PySpark 기본 사용 (pandas 대신), SQL은 Databricks SQL 문법
- Serverless 제약 준수: R/Scala/RDD/DBFS mount/init script 금지, %pip install pyspark 금지

## 네이밍
- 카탈로그: ccm_factory
- 스키마: bronze / silver / gold / quarantine
- 테이블/컬럼: snake_case

## 안전 규칙
- 기존 테이블 DROP/DELETE/UPDATE 금지, CREATE OR REPLACE TABLE 사용
- 개발/테스트 시 LIMIT 1000
- 모든 테이블/컬럼에 COMMENT 추가
- Delta 형식, event_date 파티셔닝 기본

## MCP 도구 활용 (AI Dev Kit)
- Genie Space → manage_genie, 대시보드 → manage_dashboard, Job → manage_jobs
- 파이프라인 → manage_pipeline, KA/Supervisor → manage_ka/manage_mas
- MCP 호출 실패 시 재시도, 노트북 우회를 먼저 제안하지 말 것
```

### 적용 확인

```
Custom Instructions가 적용됐는지 테스트해줘.
ccm_factory.bronze 스키마에 test_table 이름으로 1행짜리 Delta 테이블을 만들고 바로 삭제해줘.
권한·컴퓨트가 정상인지 확인용이야.
```

> 한국어 답변 + PySpark + snake_case + COMMENT면 정상 적용입니다.

## Part F: AI Dev Kit MCP 연결 (선택 — 꼭 필요할 때만)

> **원칙: 네이티브 우선, MCP는 최소화.** 이 워크샵의 대부분(데이터 생성·EDA·품질진단·SQL·파이프라인 코드·대시보드/에이전트 초안)은 **Genie Code 네이티브 기능 + Databricks UI**만으로 됩니다. AI Dev Kit MCP는 **한 대화에서 여러 제품을 자동 생성/오케스트레이션**하고 싶을 때만 켜세요. 안 켜도 각 모듈은 UI 대체 경로로 완주할 수 있습니다.

Genie Code는 각 제품 영역 **안에서는** 강력하지만, 한 대화에서 **여러 제품에 걸친 작업**(예: "Genie Space도 만들고 대시보드도 만들고 Job도 걸어줘")은 기본 기능만으로는 못 합니다. 이때만 **AI Dev Kit MCP**가 도움이 됩니다.

| 작업 | 네이티브 Genie Code + UI | MCP 있을 때 |
|------|------------------------|------------|
| 데이터 생성/EDA/품질진단/SQL | ✅ 그대로 가능 | 동일 |
| SDP 파이프라인 코드 작성 | ✅ Lakeflow Pipeline Editor에서 Genie Code | `manage_pipeline`로 생성까지 |
| 대시보드 | ✅ Dashboards → + Create (사이드 패널 Genie Code) | `manage_dashboard`로 한 대화에서 |
| Genie Space | ✅ Genie → + New | `manage_genie`로 한 대화에서 |
| Agent Bricks (KA/Supervisor) | ✅ Agent Bricks 메뉴에서 생성 | `manage_ka`/`manage_mas`로 한 대화에서 |

> 즉 **MCP 없이도 전 모듈 완주 가능**합니다. 각 모듈은 MCP 프롬프트와 함께 UI 대체 경로를 병기합니다. MCP를 쓰지 않을 팀은 아래 Step 1~3을 건너뛰어도 됩니다.

| 요청 | MCP 없이 | MCP 연결 시 |
|------|---------|-------------|
| "이 테이블로 Genie Space 만들어줘" | ❌ | ✅ `manage_genie` |
| "대시보드 + Job 스케줄 한 번에" | ❌ | ✅ 한 대화에서 |
| "Knowledge Assistant / Supervisor 만들어줘" | ❌ | ✅ `manage_ka` / `manage_mas` |

### Step 1: MCP 서버 추가

> **사전 조건**: `mcp-ai-dev-kit` 앱이 워크스페이스에 RUNNING 상태여야 합니다. (앱 이름은 `mcp-`로 시작해야 Settings에 노출됨)

1. Genie Code 사이드 패널 → 하단 ⚙️ **Settings**
2. **MCP Servers → "+ Add Server"**
3. 드롭다운에서 **`mcp-ai-dev-kit`** 선택 → **Save**

### Step 2: 도구 20개 제한 — 워크샵 프로필만 ON

AI Dev Kit은 40여 개 도구를 제공하지만 **최대 20개**만 켤 수 있습니다. Genie Code가 이미 잘 하는 것(OOB Genie 질의·Vector Search 질의·SQL 실행)은 OFF, 고유 기능만 ON.

**워크샵 권장 프로필 (올라운드 15개)**:

| # | 도구 | 용도 |
|---|------|------|
| 1 | `manage_genie` | Genie Space 생성/관리 |
| 2 | `manage_mas` | Supervisor Agent |
| 3 | `manage_ka` | Knowledge Assistant |
| 4 | `manage_dashboard` | 대시보드 생성 |
| 5 | `manage_jobs` | Job 생성/스케줄 |
| 6 | `manage_job_runs` | Job 실행/모니터링 |
| 7 | `manage_pipeline` | SDP 파이프라인 |
| 8 | `manage_app` | Databricks App |
| 9 | `manage_serving_endpoint` | Model Serving |
| 10 | `manage_vs_index` | Vector Search 인덱스 |
| 11 | `execute_sql` | SQL 실행 (우선 사용) |
| 12 | `manage_uc_objects` | 카탈로그/스키마/테이블 CRUD |
| 13 | `manage_uc_grants` | 권한 GRANT/REVOKE |
| 14 | `manage_workspace_files` | 워크스페이스 파일 |
| 15 | `get_table_stats_and_schema` | 테이블 통계/스키마 |

> `execute_code`(클러스터 실행)는 시작 대기로 타임아웃이 잦습니다. **SQL로 되는 건 `execute_sql` 우선**.

> **모듈별 추가 도구** (20개 이내에서 켜기): 데이터 생성/PySpark 시연이 필요하면 **`execute_code`**, Lakebase 실습(모듈 7 Part D, 선택)이면 **`manage_lakebase_database`** 를 추가로 ON 하세요. 위 15개 + 2개 = 17개로 20개 제한 안에 들어옵니다.

### Step 3: 연결 확인 & Warm-up

```
현재 활성화된 MCP 도구가 몇 개이고 어떤 도구들인지 목록으로 보여줘. 20개 제한에 걸리지 않는지도 확인해줘.
```

```
현재 사용자 정보 알려줘
```
> MCP 앱이 유휴 상태면 첫 호출이 10~30초 지연될 수 있습니다. 위 프롬프트로 미리 깨워두세요.

### MCP 실패 시 대응

- Genie Code가 "노트북으로 대신할까요?"라고 하면 → `아니, 다시 MCP 도구로 시도해줘.` (10~30초 후 대부분 해결)
- 계속 실패하면 UI로 우회 가능: Genie Space는 사이드바 **Genie → + New**, 대시보드는 **Dashboards → + Create**, 에이전트는 **Agent Bricks** 메뉴
